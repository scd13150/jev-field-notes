# Jev 的作用

TypeSafe 家的 Jev（当前版本 `jev-1.13.0`）常被介绍成"一个很快很小的模型"。
这个说法会误导。它的真实作用是一句话：

> **Jev 是语言和程序之间的类型适配器。它让"关于意义的问题"变成一个有类型、有概率、
> 可以被代码放进循环里判断的调用。**

下面说清楚：它补的是哪个洞、洞补上之后系统能长成什么样、以及它绝对不该被用在哪儿。

---

## 一、它补的洞：LLM 和脚本之间没有反馈信号

一个很常见的处境：程序需要知道一件**有意义**的事，但手里只有文本。

```
"这集的主角段真的出现了吗，还是只在对白里被提到？"
"页面上哪个元素是提交按钮？"
"这句文案里提到的价格，和页面显示的价格是同一个吗？"
```

代码答不了（它不懂语义）。那找 LLM？找 LLM 之后的现实是这样的：

1. 让模型输出一段话或一份 JSON
2. 解析它 —— 可能格式不对，要写 repair 重试
3. 从散文里把结论抠出来 —— 模型可能说了三句，哪句是结论？
4. **最关键：你完全不知道这次回答靠不靠谱**

第 4 条不是细节，它决定了整个系统的形状。因为没有信号，工程上只剩三种土办法：

- 用**次数**当判据："最多重试 2 轮，还不行交给人"
- 用**关键词**当判据：让模型必须在结尾写"裁决：通过"，然后 `grep 裁决`
  ——写"裁决：需改"也算通过，因为脚本只看那个词在不在
- 或者干脆**把检查降级成可选**，因为每次判断太贵

这些都是"没有边界"的样子。它们不是偷懒，是拿不到数值可Threshold。

**Jev 补的就是这个洞。** 它不吃散文出来散文，它吃文本、吐类型。

---

## 二、机制：一次请求 = 一份状态 + 一组判断

单个端点：

```
POST https://api.typesafe.ai/v1/systemone
{ "state": <文本 或 JSON>, "model": "jev-1.13.0", "questions": { ... } }
```

三种判断原语，按你需要哪种答案形状选：

| 原语 | 问的是 | 返回 | 典型用途 |
|---|---|---|---|
| **Choice** | 这几个选项里是哪个 | 选项 + **全量概率分布** + 置信度 | 分派、选定、归类 |
| **Score** | 在这条刻度的哪一档 | 档位坐标（可落在两档之间）+ 分布 + 置信度 | 分级、排序 |
| **Noul** | 这个陈述为真的概率 | 0–1，**没有置信度** | 检测、准入、弃权 |

关键区别：**答案空间是你给的**。Choice 只会返回你列出的键之一，
它不会幻觉出一个你不认识的选项。所以"解析 + 校验 + 修复"这一整层消失了。

---

## 三、表达力比"分类器"大得多

最常见的低估是把 Choice 想成"六选一"。实际上 `instructions` 和 `criteria` 的**值本身可以是 JSON**：

```json
"criteria": {
  "billing": {
    "what": "扣费、账单、退款、订阅",
    "not_for": "订单物流、账号登录",       ← 负定义，划清边界
    "examples": ["我被扣了两次", "我的退款呢"]
  }
}
```

- Choice 选项 → 可以带**负定义 + 示例**，等于在给类型写边界
- Score 档位 → 可以带 `signals[]`，于是 Score 是一份**评分细则**而不是量表
- 选项的值 → 可以是**整棵子树**（把分类树摊开让它看清分支里有什么再决定，代码走树）
- 有通用形状 `field = {name, type, unit, description}`，同一份定义能驱动验值(Noul)、
  选值(Choice)、定档(Score)

而且**一次请求可以问几十到上百个问题**，全部并行、共享同一份状态。加问题的边际成本几乎只有
那几行问题本身的 token —— 官方测过 13 问合 1 次请求：便宜 11.5 倍、快 9.6 倍、答案不变。

这就带来一个反直觉但很重要的编程方式，叫**投机扇出**：
不要先判断"这个问题需不需要问"，把**整个可能的意图空间一次性问完**，代码事后丢弃用不上的答案。
在还没知道用户是不是要控制灯之前，就先把"该对灯做什么操作"问出去。

## 四、洞补上之后，系统能长出什么

这才是"作用"的实质部分 —— 不是同一个流程变快，是多了三种原来做不到的结构。

### 1. 定位（而不是结论）

原来：一次审查产出一份散文报告，末尾写"通过/需改"。
现在：20 个镜头，每镜一个浮点数。**于是第一次能说出"是第 4 镜有问题"，而不是"这集有问题"。**

### 2. 会自己收敛的循环

有了数值，就能写"只对低于阈值的项重跑，直到达标或连续两轮不变"。
原来的"最多 2 轮然后甩给人"，本质是因为没有"这轮比上轮更确定了吗"这个信号。

### 3. 弃权成为一等结果

置信度（Choice/Score 自带）和概率（Noul 自带）允许系统说**"这条我不确定，别自动处理"**。
一个通用分档：

- 高置信 → 自动执行
- 中置信 → 执行但标记待复核
- 低置信 → **不执行**，转人工

这在散文机制里结构上不可能 —— 散文没有阈值。它带来的实际收益是：
100 个变体不需要人看 100 遍，只需要人看机器标红的那几处。

### 4. 分布可以当数值用（不只是取第一名）

官方明确说明 "jev-1.13 is extremely consistent：语义相似的输入给定量相似的输出"。
这意味着**固定一套问题跑出来的概率向量可以当嵌入使用**：相似度、去重、最近邻、
或者作为特征喂给下游真正的机器学习模型。只读 argmax 是扔掉信息量最大的部分。

### 5. 它可以反过来监督其他 AI

判断的对象不一定是数据，也可以是**别的模型的产出**：prompt、抽取结果、推理轨迹、
tool call 调用参数、LLM 回复。检测注入、检测幻觉、检测工具调用格式错、检测违反策略。
因为一次判断的成本只有被监督那次调用的零头，这种监督**才可能常驻在环里**。

## 五、什么时候该用：五条同时成立

1. 这是**语义**判断（不是算术、不是格式合规）
2. 证据**在文本里可得**（或者已有把非文本转成文本的上游）
3. **重复很多次**（每镜、每资产、每变体、每次请求）
4. **有执行器** —— 答案能改变某个具体的东西（改一个字段、走一个分支、拦一次发布）
5. 需要在**人/编码 agent 不在场时可复现地跑**

第 3、5 条最常被忽略。**一次性的判断，交给能看全局的编码 agent 质量更高** ——
Jev 的优势只在"要在我离开之后重复跑，并且要给同样的答案"时才出现。

"没有执行器的判断是装饰"这条尤其要守住：一个判别器如果对 4 种不同输入都给同一个答案，
那它等价于代码里写个常量，成本 0、延迟 0，接模型纯属自我感动。

## 六、什么时候绝对不该用

| 不要做 | 原因 |
|---|---|
| 让它算任何东西 | 计数、日期比较、时长累加、正则能做的字符串检查（比如"字段里有没有 ★ 号"）都不行。**机械可判的一律代码** |
| 用 Score 的数值插值出精确量 | 官方明令禁止，档位间的数值没有标定意义。Score 只能用来过阈值 |
| 让它生成文本、代码、解释 | 它不是生成模型，硬用 Choice 链式生成"不好用且极慢"。**LLM 生成 → Jev 定型**，它替代解析层不是替代模型层 |
| 让它看图像/音频/视频 | 当前只吃文本。像素判断必须先有上游转成描述/OCR/DOM 文本 |
| 把不相关的上下文一起塞进去 | 状态越大越差（context rot），既降精度又让错误无法归因。先检索过滤再问 |
| 单发、需要全局创作语境的判断 | 见第五节第 3、5 条 |
| 用 Noul 的阈值去卡 Choice，或反之 | 两种原语之间没有算术恒等式。`P(x) ≠ 1 − P(not x)` |
| 只用 Choice 回答"到底有没有合适的" | Choice 概率恒为 1，**没有好选项也照样给你排第一**。必须额外配一个准入 Noul |

## 七、必须知道的坑（都有代价）

**它对中文（以及所有非英文）明显更弱。** 在同一批真实中文素材上做过 A/B：
同一组英文问题，只换状态语言 —— 英文 3/3 判对，中文 1/3。
但**两次答错的置信度恰好落在 0.31 和 0.53，三次答对的都 ≥0.82**，
所以一个 ~0.6 的门限能自动把错误拦下来。
→ 实际做法：**给判别用一份英文镜像字段**（原文仍是画面/文案权威），并且**按置信度分档处置**。
另外"用中文写问题"没测过，别假设可行。

**高置信 ≠ 正确，它甚至可能答的不是你问的。** 实测一个反例：把规则明确写成
"判据只有一个：段名里含 ★ 号即为主角段，不要根据画面质量重新挑选"，
并且 `inspect` 只指向那个字段（值里确实没有 ★ 号）—— 模型仍然给了 0.96 的"是"。
它读了画面内容，判断那一镜"确实像个主角时刻"，然后拿这个意思**盖过了你写的机械规则**。
→ 官方列的第一号失败模式"读得太字面"是**双向的**：该字面的时候它会过度解读。
所以边界要保留人工抽查，不是设了阈值就能撒手。

**模型版本要当依赖钉死。** `jev-latest` 是别名，会随发版漂移，答案可能在没有代码改动的情况下变化。
生产上用 `jev-1.13.0`；升级模型 = 全量重跑 + diff，按编译器升级对待。

**状态内容可能被"自我论证"带偏。** 它默认不把 state 当敌意输入。
如果判别对象是抓来的网页、用户评论、或别的模型的输出，注入和诱导是真实风险。

**瞬时失败是常态不是异常。** 实测会撞到 SSL 连接中断，也有限流（429/529）。重试和退避必须自己写。

## 八、本机实测数字（公开网络，2026-09）

| 项 | 值 |
|---|---|
| 价格 | 输入 $42/Btok（= $0.042/Mtok），**输出免费** |
| 小状态 1 问（约 280 token） | **p50 769ms / p90 1380ms** |
| 4 问约 1000 token | ~790ms/次 |
| 真实一次：5 镜 × 3 判断 = 15 问 | **1.2 秒，4313 token，$0.00018** |
| 复现性：同输入 15 次 | 标签 3/3 项全部 15/15 不变；**但 conf 可飘 ±0.12** |
| 上下文预算 | 单请求 64k token；state + 最长问题 32k |

注意：官方宣传"real-time 150ms"。这台机器上拿不到，差 5 倍。
所以它能做的是**步级**判断（每次保存、每个资产、每次变体），做不到键击级/帧级。

## 九、最小可用形状

```python
import os, json, urllib.request

def judge(state, questions, model="jev-1.13.0"):
    body = json.dumps({"state": state, "model": model, "questions": questions}).encode()
    req = urllib.request.Request(
        "https://api.typesafe.ai/v1/systemone", data=body, method="POST",
        headers={"Authorization": "Bearer " + os.environ["TYPESAFE_API_KEY"],
                 "Content-Type": "application/json"})
    # 指数退避：429/529/瞬时断连都是常态
    ...
    return json.loads(urllib.request.urlopen(req, timeout=60).read())

shots = {...}                      # 你的状态：由代码准备，不是手抄
questions = {
    "core_visible_%d" % i: {       # 逐实例提问，一次请求全问完
        "type": "noul",
        "instructions": {
            "question": f"shots[{i}].visual 里，核心主体是否实际出现在画面中？",
            "rule": "只在声音/对白里被提到，不算。",
            "inspect": f"shots[{i}].visual"},
    } for i in shots
}

ans = judge(state, questions)["answers"]
# ↓ 以下全是代码的活：阈值、聚合、定位、写回、决定是否阻断
bad = [i for i in shots if ans["core_visible_%d" % i]["noul"] < 0.5]
```

**注意这个分工：Jev 只回答"这一镜出现了吗"。阈值多少、哪些要重跑、结果写回哪儿、
要不要阻断发布，全部是你的代码。** 政策永远是显式的，模型只提供判断。

## 十、最后

把它当"小模型"就会问"它能替代什么"，然后处处不够格 —— 它不算术、不生成、不看图。

把它当**边界类型**就清楚了：它让"意义"第一次变成代码可以合法消费的东西，
而且便宜到**每个边界都能放一个**，可靠到**它自己会报告这次有多可信**。

代价是它会把"你问的"和"它理解的意思"搞混，而且搞混的时候语气很确定。
所以它是边界，不是裁判。
