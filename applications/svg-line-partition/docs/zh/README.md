# 用 Jev 对 SVG 线条画做初始条件的模糊划分：能力上限探测

一个独立的实验子项目。目的只有一个：**测出 Jev（TypeSafe 的 System One 模型）
在只有文本输入的前提下，对一张线条画的"初始条件"能做到什么程度的模糊划分**——
层级能不能分、区域能不能分、元素之间的关系能不能分，以及它的置信度能不能信。

跑了四轮。§1–§6 是第一轮：消融**几何怎么写**（原始路径 / 特征表 / 匿名 / 命名 / 假坐标）。
§7 是第二轮：换三幅保留**绘画痕迹**的新画，消融**痕迹怎么写**，
问题是机器重绘 / live2d 真正要的那四件事——部件归属、层级角色、区域划分、运动归属。
§8 是第三轮：不画完再读，而是**笔还在手里的时候能不能参与决策**——选候选、配对称件、
查缺笔、找画歪的那一笔、猜下一笔。这一轮的真值是代码扰动造出来的，所以基线是真正的 1/K。
§9 是第四轮：**反过来用它替我画**——我写配方和网格，它选数字，脚本按数字落笔；
顺带把同一套题的**输入端**改了一遍，量出"我上一版把多少东西写坏了"。

结论写在下面，全部数字来自本目录的实际运行（第一轮完整表格在 `results/report.md`，
第二轮在 `results/traces/report.md`，第三轮在 `results/drawloop/report.md`，
第四轮在 `results/drawwith/report.md`，
`results/viewer.html` 可以逐笔画查看每条判断）。

**只想看结论就读 §10**：四轮的汇总表、跨轮一致因此可以当事实用的六条、
以及一直欠着的两块（没有刻度、执行端欠债），还有两个参考项目里能借的和借不到的。

## 1. 一句话结论

**Jev 能在线条画上做出可用的软划分，但它划的是"这份 state 叙述的画"，不是"真的那张画"。**
凡是能从坐标读出来的东西（九宫格区域、包含关系、列表里的先后），给它坐标它就答得准，
坐标系一假造立刻散架；凡是画师约定（谁代表远景、哪个部件属于哪个物体），
它必须靠命名或作者写的 `<g>` 树，只给几何时会给出另一种同样自洽但不正确的划分（切得过碎，从不跨物体合并）。
两条最该记住的：**它读假坐标时和读真坐标一样自信**，以及
**它能把"谁先画"答到 1.00，却不会把这个事实当"谁在前面"的证据用**——见 §5 与 `results/report.md` §9。

| 维度 | 上限（实测） | 依赖的线索 |
|---|---|---|
| 层级·嵌套深度（被几层闭合线包住） | 只给坐标时命中率 0.57–1.00、宏 F1 比"恒定答多数类"高 +0.31 至 +0.52；同时给名字反而掉到基线以下（§5.2） | 只有坐标，且名字会干扰 |
| 层级·场景深度（远/中/近平面） | 有名字的语义画 0.71–0.97；零语义的匿名画 0.29–0.62，且 95% 的元素自己落进"弃权"档 | 命名 / 作者 `<g>` 树 |
| 区域（九宫格） | 只给坐标 0.57–0.86；坐标置换后 0.00–0.22，每幅都跌破自己的多数类基线（0.25–0.36） | 只有坐标 |
| 关系·包含 / 绘制顺序 | 命中率 1.00、AUC 1.00，而且正例占 29% / 49%——不是"恒定答一边"能白拿的 | 坐标（顺序题连坐标都不需要，只读列表位置） |
| 关系·相接 / 交叉 / 同属一物 | AUC 0.81–0.95 有信息，但命中率相对基线只有 −0.02 至 +0.07：类别偏斜，别读命中率 | 坐标 |
| 关系·前后遮挡 | 有断口线索的 8 对 AUC 1.00；**没有线索时命中率 0.53、基线 0.60、AUC 0.39**——它会读绘制顺序却不用它推前后（§5.5） | 断口线索 |
| 归属分组（物体级划分） | 有命名时 ARI 0.94–1.00，但那基本是照抄作者写的 `<g>` 树（§3.1 的混淆项）；只给几何 ARI 0.00–0.69，失败方式是"只切不合"（32 笔预测 23 簇 vs 真值 11 个物体，跨物体错误合并 0 次） | 命名 / `<g>` 树 |
| 分级·跨度 | Spearman 0.93–0.96；绝对档位命中只有 0.43–0.76；坐标置换后序会反转（−0.58 至 −0.03） | 坐标 |
| 分级·结构权重 | Spearman 0.46–0.82，比跨度弱，且更容易被语义带走而不是被数字带走 | 两者混合 |
| 整图·有没有画生物 | 12/15 与内核一致，唯一分歧是"两只三条线的鸟"这种真模糊样本，它给的是 0.33–0.38 而不是硬猜 | 两种都行 |
| 整图·有几个深度平面 | 0/15——定义不一致（它把边框算作一层），连续分其实跟着线索动 | 见 §5.4 |

一句话读法：**命中率高的行要看基线，基线已经很高的行去看 AUC 和 Spearman。**

第二轮（§7）补一句：**把绘画痕迹喂进去，部件归属能做到 10–11 类全对、ARI 1.000，
但那格的主因是元素 id 就是部件名——真实笔迹顺序单独只值 +0.003，而一套自洽的假顺序是负资产。**

## 2. 怎么跑

```bash
cd svg-line-partition-jev
set TYPESAFE_API_KEY=...            # Windows: 用 export/set 视终端而定
python -m src.selftest              # 几何内核自检，不需要网络与 key
python -m src.run_probe             # 全网格；结果落在 results/raw + results/cache
python -m src.analyze               # -> results/report.md
python -m src.make_viewer           # -> results/viewer.html（单文件，可直接双击打开）

python -m src.run_traces --check    # 第二轮离线闸门（不联网、不计费）
python -m src.run_traces            # 第二轮 3 幅 × 5 痕迹条件网格
python -m src.traces_report         # -> results/traces/report.md

python -m src.run_drawloop --check  # 第三轮离线闸门（不联网、不计费）
python -m src.run_drawloop          # 第三轮 5 家族 64 个循环内 state

python -m src.run_jvdrawing --check       # 第四轮离线闸门（不联网、不计费）
python -m src.run_jvdrawing --input both  # 第四轮：两种输入端各画一遍 -> results/drawwith/
python -m src.run_jvdrawing --no-calls    # 只跑代码基线并出图，不计费
```

`run_probe` 按 `(model, state, questions)` 做磁盘缓存，重跑不重复计费；
`--only house_scene/features_named` 可以只跑单个组合。
模型钉在 `jev-1.13.0` 而不是 `jev-latest`，因为置信度阈值一旦调好就不该被别名搬家影响。

整个网格（15 个组合、4,905 条判断、797k 输入 tokens）实测花费约 **\$0.033**，
API 侧累计 57.9s（约 3.9s/组合，45 次调用、每次打包 ~109 个问题）。
也就是**一幅 32 笔的画做一整套划分约 \$0.002**（输出不计费）。

## 3. 实验设计

### 3.1 为什么"怎么文本化"就是主变量

Jev 只吃文本（官方文档 Models → Input：text only）。所以一张画必须先变成 state，
而"变成什么样的 state"直接决定它能答什么。五档条件是故意拉开的梯度：

| 条件 | state 内容 | 作者 `<g>` 树 | 想问的问题 |
|---|---|---|---|
| `features_named` | 元素名 + 全部几何特征 | 有 | 上线形态长什么样 |
| `features_anon` | 匿名 id（e-01…）+ 全部几何特征 | **无** | 它到底读不读坐标 |
| `named_nogeo` | 只有元素名，无坐标 | 有 | 它是不是只靠名字猜 |
| `raw_paths` | `d` 属性原文 + 画布尺寸 | 有 | 不做预提取行不行 |
| `scrambled` | 几何特征在元素间随机置换 | 有 | **假证据对照**：证明它真在用坐标而不是在编 |

最后一列是读结果时不能忘的**混淆项**：五档里有四档都带着作者写的 `<g>` 树，
而树本身就是层级和归属的一种现成答案。所以"有名字那几行"的高分里，
有多少是推理、有多少是照抄文件结构，分不开——真正只考"从坐标里发明分组"的
只有 `features_anon` 一档。`raw_paths` 之所以比 `features_anon` 在职责、场景层级、
分组上都高，一部分原因就在这。

给模型的几何特征是"原料"而不是"答案"：id、形状类型、采样后的点骨架、
描边长度、外接框、是否闭合、总转角、主方向。像"被几层包住""属于哪个重复族"
这类会泄漏真值的派生量一概不给，由 `serialize.leak_check()` 在发请求前自检，
真值字段（`data-truth-*`）在序列化时剥掉，剥不干净就直接抛 `AssertionError`。

### 3.2 三幅画各卡一种能力

- `fixtures/house_scene.svg`：400×300，32 笔，DOM 嵌套 = 物体层级。栅栏立柱与太阳光芒
  是刻意造的**重复纹理族**（检验它能不能发现"这 6 笔是一组"）。窗框与窗棂、门与墙
  是**边界相切**的包含关系（检验容差）。
- `fixtures/kick_figure.svg`：380×300，14 笔，画的是一个踢球的人。两条 `far-arm-*`
  是**同一条手臂被躯干断开**，父 `<g data-truth-behind="torso">` 检验组真值能否继承到子元素；
  `foot` 与 `ball` 之间留 1.1px 间隙，是一个"看着接上其实没接上"的近邻负例。
- `fixtures/abstract_nesting.svg`：360×300，21 笔，id 匿名（n-01…n-21）、组名不透明
  （ga…gf）、**零语义线索**。并且故意让 DOM 嵌套与几何包含不一致——就算 state 里带着
  `<g>` 树，"谁在谁的树里"也答不对"被几层闭合线包住"。这幅画的元素全都没有物体标签，
  所以它的归属只能从成对"同属一物"判断里读，ARI/NMI 那套对它按定义跳过。

### 3.3 真值与指标

两条路互为对照：

1. **几何内核**（`src/svggeom.py`）自己算：路径展平（含圆弧端点→圆心换算、
   `transform` 矩阵）、按固定弧长步长重采样后的总转角（所以直线≈0、圆/矩形恰为 360°）、
   点在多边形内（含容差，判"被包住"）、线段相交、最小间距、九宫格区域、重复族检测。
2. **作者标注**：SVG 上的 `data-truth-layer/role/object/group/behind`，
   组真值自动继承给子元素。

指标不用单一命中率糊弄自己（`src/metrics.py`）：
`n / acc / macro-F1` + **多数类基线与恒定回答的宏 F1 基线**（真值偏斜时命中率没意义）+
按置信度三档分流（≥0.85 直接行动 / 0.55–0.85 人工看 / <0.55 弃权）的覆盖率与分段命中率 +
校准分箱 + 归一化熵 + 多类 Brier + 成对关系的 AUC + 分级判断的 Spearman。

**模糊划分**的核心指标是这一条：把每个元素的分组后验还原成两两共属概率
P(同组) = Σ_g p_a(g)·p_b(g)，单链接聚类成划分，再对真值划分算 ARI/NMI，
并且分开统计"**多元素簇数**"（够不够合并）和"**跨物体的簇数**"（有没有合错）。

成对关系的候选由内核挑（包含、相接、同物近邻、异物近邻、最远负例，每幅 21–26 对），
但**挑完之后必须检查每一类关系的正负比例**：第一版把每对都按"文档里靠前的那个"排在前面，
于是"第一个是否后画"变成了只有一类的问题，恒定答"否"就能拿 1.00。
现在的做法是隔一对交换 a/b 方向、有遮挡线索的对按两个方向各问一次、每种关系单独配额，
命中率才等于本事而不是白拿。报告 §1 里真值单类别的行都打了 `*`。

一次请求把所有问题打包发出（同一 state 上的判断彼此独立，服务端并行评估）。
问题一律用反引号引用 state 路径（`` `state.elements[17]` ``），
易混选项用结构化 criteria 写清 `what` / `not_for`
（[primitives/advanced](https://docs.typesafe.ai/primitives/advanced.md)），
Score 的每个档位描述一个具体情境而不是程度副词
（[primitives/score#writing-good-levels](https://docs.typesafe.ai/primitives/score.md#writing-good-levels)），
一次请求里把所有独立维度并行发起（[patterns/fan-out](https://docs.typesafe.ai/patterns/fan-out.md)）。

## 4. 分层读结果

`results/report.md` 按 §0 条件说明 → §1 上限总览 → §2 逐元素（命中率 / 两种基线提升 / 置信度）→
§3 消融 → §4 分组（ARI/NMI、只切不合）→ §5 置信度是否跟着证据走 → §6 校准表 →
§7 整图判断 → §8 具体失误样本（可以照着 `viewer.html` 点）→ §9 这份上限怎么读。
看的时候只有一件事不能省：**先看清基线再看命中率**，真值偏斜时 1.00 可以是不费吹灰之力。

## 5. 失效模式（这部分最该记进设计笔记）

### 5.1 它不为证据的真伪负责

`scrambled` 条件下，区域判断的命中率与置信度是这样的（"真坐标"列取 `features_anon`）：

| 画 | 真坐标命中率 | 真坐标置信度 | 假坐标命中率 | 假坐标置信度 | 自己的多数类基线 |
|---|---|---|---|---|---|
| abstract_nesting | 0.857 | 0.868 | **0.048** | **0.842** | 0.286 |
| house_scene | 0.812 | 0.782 | 0.219 | 0.788 | 0.250 |
| kick_figure | 0.571 | 0.701 | 0.000 | 0.638 | 0.357 |

置信度几乎不掉，命中率跌到基线以下。它没有"这些坐标互相矛盾"这类怀疑能力：
state 说什么，它就按什么推断。反过来，`named_nogeo` 条件下区域置信度只有
0.35–0.42、高置信覆盖率 0.00–0.07 —— 没得读的时候它确实不硬猜。

所以：**置信度衡量的是"这份 state 里有没有可依据的线索"，不是"线索是不是真的"。**
上游管线（SVG 解析、坐标提取）必须自己保证正确性，本项目的做法是几何内核 +
`selftest.py` 里的解析断言（圆面积 ±1.2%、n-05 嵌套深度 ==4、族检测、
mullion ⊂ window-frame、门 ⊂ 墙、组真值继承、转角统计），把它当作进入 Jev 前的强制关卡。

### 5.2 两种层级定义会打架

`nesting_layer`（被几层闭合线包住）是纯几何量，`scene_layer`（远/中/近）是画师约定。
同时给名字和坐标时，`nesting_layer` 在 house_scene 上的命中率 0.594 **低于**
恒定答"一层"的 0.844，宏 F1 也刚好等于恒定回答的宏 F1（0.229 对 0.229）；
在 kick_figure 上宏 F1 0.271 更是低于恒定回答的 0.481。
名字把它拉向语义深度（"墙是远景所以算在外层"），于是它不再回答"被几层线包住"。
只有零语义的 abstract_nesting 上，带名字的宏 F1（0.532）还高出恒定基线（0.191）一截。
也就是说：**它在判断，只是用的是另一种同样合理的层级概念；而概念一冲突，
给了名字反而没有只给坐标准**（`features_anon` 的宏 F1 0.534 > `features_named` 的 0.229）。

工程含义：一个维度只问一个问题，而且问题里必须把定义写死（"被几层闭合线包住"
就比"它在第几层"可靠），否则它会回答你没想要的那个答案。这不是它不听话，
是两种层级本来就有两种正确答案。

### 5.3 Score 能排序，不能直接分箱

`extent`（跨度）在只给坐标那档的 Spearman 高达 0.93–0.96，但绝对档位命中率只有 0.43–0.76，
且 `mean_confidence` 0.74 —— 它对"这条线挺长"很有把握，对"该算第几档"没把握。
`scrambled` 下 Spearman 变成 −0.58 至 −0.03，序会反过来。
所以：**用它排序、用它挑 top-N、别把它的分数当离散标签直接落库。**
需要离散档位时，用代码对它的连续分做分位切分，档位定义权留在自己手里。

`structural_weight`（结构权重）同理但更弱：Spearman 0.46–0.82（跨度是 0.93–0.96）。
而且它是两个连续维度里唯一一个"只给名字"能在某幅画上赢过"只给坐标"的
（house_scene：0.507 对 0.463），说明它读的是叙事重要性而不是几何显著性——
问"这条线有多重要"比问"这条线有多长"更容易被语义带走。

### 5.4 计数类整图判断被定义绑住

`gestalt_layer_count` 15 次全与内核不一致：内核按作者标注的深度平面数（3），
它多数条件下答 4 —— 它把外框也当成了一层。连续分其实跟着线索走
（只给坐标时三幅都是 0.97–1.31，读作"就一个平面"；有名字的语义画上爬到 2.06–2.87，
离真值 3 只差那一层边框），错的是档位映射而不是线索读取。
这类问题要么把计数规则写进 criteria（"边框不算一层"），
要么改成由代码从逐元素层级聚合。

另外三条整图判断（有没有画生物 12/15、主方向 4/15、视觉重心 8/15）的真值
都是代码定的**代理定义**，不一致里有多少是它的错、有多少是定义太粗，
报告 §7 逐条算了账，读的时候连同定义一起读。

### 5.5 读得出顺序，不等于会用顺序判断前后

这是把成对真值做成两类以后才露出来的新发现。同一批笔画对：

- 直接问"这两条线谁后画（谁盖在上面的绘制顺序）"：三幅画命中率都是 **1.00**，
  多数类基线 0.51，正例占一半——它是真在读 state 里列表的位置，不是猜。
- 问"这两条线谁在谁前面"而**不**给断口线索：命中率 0.53（基线 0.60）、AUC 0.39，
  五种条件下都在抛硬币附近。
- 一旦有断口线索（手臂被躯干截断），8 对里 AUC 1.00。

也就是说：知识在那儿，但它不会主动拿去做别的维度的推断。
工程含义是**别指望模型自己组合事实**——需要"绘制顺序 → 前后"这条推理链时，
在代码里把它写成一条规则，或者把它做成问题里的显式线索，不要留给它联想。

### 5.6 这些失误对得上厂商自己列的 jaggedness

[Jev 1.13 jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md)
（本页实测所用版本，文档标注 last reviewed 2026-09-17）列了 9 条已知毛病，
本项目的失效点几乎逐条落进去：

| 官方条目 | 本项目对应观察 |
|---|---|
| "answers the question you wrote, not the one you meant" | 问"第几层"它答语义层级，问"被几层闭合线包住"才答几何层级（§5.2） |
| "does not count reliably … the error grows with the size of the thing" | `gestalt_layer_count` 15/15 不一致，且错法是稳定地多算一层（§5.4） |
| "tasks that require additional levels of indirection" | 读得出绘制顺序，却不用它推前后（§5.5） |
| "don't hold the model to arithmetic identities between separate questions" | 所以成对判断必须按两个方向各问一次来验类别平衡，而不能指望 a→b 与 b→a 自相一致 |
| "Large state full of irrelevant detail" | state 里同时带 `<g>` 树时，分组和职责的高分里混着照抄树结构的部分（§3.1 的混淆项） |

这条对使用方的意义是：**厂商文档里的"已知边界"是可复现的，不是免责声明。**
在换模型版本之前，先把这张表当成回归清单。

## 6. 如果要在工作里用这套东西

推荐的分法（本项目就是这么设计的，也是数据支持这么做的顺序）：

1. **硬事实留在代码里。** 坐标、包围盒、长度、转角、包含关系、相交、间距、族检测——
   这些是可精确计算的，交给 Jev 只会引入不必要的不确定性，而且它答对了你也不知道
   它是算对的还是猜对的。本项目的做法是：内核算，`selftest.py` 证明它算对。
2. **需要语义的模糊划分交给 Jev。** "这笔在画里承担什么职责""这块是背景还是主体"
   "哪些部件属于同一个物体""按视觉重要性排序"——这些没有确定性算法，
   而它的软划分（一整条概率分布）比一个硬标签更有用：可以分流、可以加权、可以复用。
3. **state 里同时给命名和几何，但别把两者的功劳记混。** 消融显示两者互补而不是替代：
   坐标型维度靠 `features_anon` 也能答（原始 `d` 串条件下跨度 Spearman 仍有 0.88–0.94），
   约定型维度必须靠名字；只给一半时另一半就掉到基线附近。
   但要记住名字那几档都自带 `<g>` 树，所以"命名很准"里有一部分是"文件已经写好给它看"。
   想要一个不靠作者约定的读数，只看 `features_anon`。
4. **按置信度三档分流，不要用一个阈值。** 本项目 ACT=0.85 / CAUTION=0.55
   （官方把这叫 confidence 作为第二根轴，见
   [confidence-gated routing](https://docs.typesafe.ai/patterns/confidence-routing.md)）：
   在真线索充分的维度上，高置信段的实测正确率 0.80–1.00（中位 1.00），
   弃权段中位只有 0.46；而没有线索可读时高置信覆盖率自己塌到 0.00–0.07（区域 × 只给名字）。
   也就是**分档不需要额外调阈值**，它自己会告诉你哪些样本它没依据。
5. **每次换 state 形态就重测一遍。** 同一条判断换一种文本化，数字可以差得很多：
   `nesting_layer` 在 house_scene 上 `features_anon` 命中 0.781、`raw_paths` 只有 0.312；
   反过来 `role` 在 kick_figure 上 `features_anon` 0.643、`raw_paths` 0.929。
   厂商的 [jaggedness](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md) 与
   [confidence](https://docs.typesafe.ai/confidence.md) 两页都在说同一件事：
   阈值要在自己的数据上定，别把一次调好的阈值当成模型属性。

一个自然的延伸（本项目未做，但数据结构已经支持）：把它的概率当特征喂给下游
经典模型（[AutoResearch 特征发现 cookbook](https://docs.typesafe.ai/cookbooks/autoresearch_feature_discovery.md) 的路子），
或者用 `rel_evidence` 这类元判断先把"没证据"的样本剔掉再进分类。

## 7. 第二轮：把绘画痕迹喂进去（机器重绘 / live2d）

第一轮那三幅画没有痕迹，而且都带作者写的 `<g>` 分组树——所以"命名条件下 ARI 0.94–1.00"
里有一部分其实是"文件已经把答案写好给它看"（§3.1 的混淆项）。第二轮把这根干扰拔掉了：
新画的三幅 `fixtures/trace_*.svg` 全文件只有**一层** `<g>`，仅用于统一描边样式，
`group_path` 对每一笔都相同，没有任何部件层级可抄；部件归属只能从几何、语义和笔迹里读。
每笔带 `data-t`（落笔时刻）和作者标的 `data-truth-part / -layer / -motion` 三样真值，
区域真值则改由代码算（每幅画自己的矩形分块 + 沿弧长每 1 点采样，过半即归属，否则 `spans-several`）。

消融的变量从"几何怎么写"换成"**这幅画是怎么被画出来的这件事怎么写**"，五个条件：

| 条件 | state 里有什么 | 单独隔离了什么 |
|---|---|---|
| `order_named` | 数组顺序 = 笔迹顺序 + `trace_ms` + 元素 id 就是笔画名 | 上界（名字与痕迹同时给） |
| `order_list` | 同上，但 id 换成 `s01…` | 把名字拿掉，只剩痕迹 |
| `times_only` | 数组按位置排序（与笔迹无关），`trace_ms` 是真时间，note 明说要自己比数字 | 顺序不在列表位置上，要它自己算 |
| `order_none` | 没有 `trace_ms`，note 明说这里没有顺序 | 什么痕迹都不给 |
| `order_scrambled` | 数组顺序与时间戳都是**假的**但自洽，note 一样叫它信 | 假证据控制组 |

三幅画各带一个难点：火柴人按部位连着画（痕迹与部件重合，用来量上界）；
房子打乱着画（栅栏三根柱子被门、屋顶、窗隔开，用来量痕迹到底有没有用）；
猫是装饰陷阱（五根一模一样的开曲线，有的算毛有的算胡须，笔顺里交替出现）。

### 7.1 读数（三幅平均，逐幅见 `results/traces/report.md`）

| 维度 | 名字+顺序 | 只有顺序 | 只有时间戳 | 什么都没给 | 假痕迹 | 多数类基线 |
|---|---|---|---|---|---|---|
| 部件归属 | **1.000** | 0.781 | 0.749 | 0.779 | 0.752 | 0.178 |
| 区域划分 | 0.908 | 0.923 | 0.909 | 0.894 | 0.940 | 0.343 |
| 层级角色（五档） | 0.701 | 0.554 | 0.614 | 0.628 | 0.556 | 0.402 |
| 运动归属 | 0.776 | 0.679 | 0.705 | 0.706 | 0.661 | 0.342 |

区域那一行五个条件都不动——它是这一轮的内对照，说明条件真的只改了痕迹这一件事。

### 7.2 这一轮的结论

1. **给名字 + 给真笔迹顺序，部件划分可以直接落库**：三幅 1.000 命中、宏 F1 1.000、
   ARI 1.000、聚出的簇数 11/10/10 与真值部件数完全一致、跨部件混簇 0 次。
   对着的是 0.143/0.174/0.217 的多数类基线，10–11 类问题全对不是撞的。
2. **但那一格是"名字与痕迹同时给"才有的，而且主因是名字**：把 id 换成 `s01…`
   平均立刻掉到 0.781（打乱那幅房子 1.000→0.696）。反过来，
   `order_list` 对 `order_none` 只差 **+0.003**（火柴人 +0.095、房子 +0.000、猫 −0.087）——
   **真实笔迹顺序单独几乎不值钱**，部件的身份来自这条线画的是什么、在哪里，不来自它是第几笔。
3. **假痕迹是负资产，而且不掉置信度**：房子那幅 0.696（什么都不给）→ 0.522（假痕迹），
   答错时的平均置信 0.497，比无痕迹时答错的 0.417 还高。
   **上游录不到真实笔迹时，宁可不给，也别给一个看起来自洽的顺序。**
4. **区域划分是免费的**：0.915 上下，不需要名字也不需要顺序，把矩形定义写进 state 就够。
5. **五档层级角色是这次最弱的一维**（0.701 上限，基线 0.402，且 `decor`/`detail` 本来就互相混淆），
   但它在这维上**会诚实地弃权**：猫那幅覆盖率从 0.522 塌到 0.087。
   工程上换成一条 Noul——"这根开口线能不能单独一层"：**recall 1.000、AUC 0.972**，
   真为正均值 0.852 对真为负 0.214；precision 只有 0.657，误报里栅栏四笔是真错、
   衣褶墙裂反而本来就该单独一层。所以**当筛选器用，别当真值**。
6. **读得出顺序 ≠ 会用顺序**：只有时间戳时"谁先画"仍有 0.872（自己比数字比得动），
   但"这两笔是不是连笔"只有 0.493，**低于它自己的常数答基线 0.551**；
   整图那条"这份 state 读不读得出顺序"的 Noul 在同一条件下也只有 0.89（真痕迹下 0.97、无痕迹 0.03）。
   **"按笔画段自动分组"这种省事做法不要指望它**——分段用代码算走位距离（AUC 0.929–0.967，可精确算）。
7. **成对题与逐元素题会互相打脸**：同一批笔画，`part` 1.000 而 `p_same_part` 0.819，
   两条路答案一致率最低 0.538。词表在手上时分得开毛与胡须，
   只问"这两根算不算一个部件"时就算不开。**带词表的 Choice 当主判据，成对 Noul 只当复核。**
8. **ARI 要连着簇数读**：`order_list` 在房子上 ARI 0.084 而 NMI 0.843、top-1 命中 0.696，
   簇数却从 10 涨到 22——不是聚错，是分布摊开、Σp_a·p_b 过不了 0.5 的合并门槛。

落到 live2d 式的最小分工：代码负责一切可精确算的事实（点列、闭合、包含、走位距离、
时间戳排序、区域矩形），并把元素 id 起成有意义的部件名；Jev 一次并行请求负责
part / region / motion 三个带词表的 Choice 加一条装饰线 Noul；代码再把 Choice 的
整条分布折成软划分（ARI/NMI 连簇数一起复核）与浮动层清单。

## 8. 第三轮：笔还在手里时的判断（循环内）

前两轮都是"画完了再读"。这一轮换问题：**画到一半时能不能用它做决策**。
麻烦在于循环内的判断没有现成真值——"这笔好不好"没人标得起。于是真值改成代码造：
拿真画里已有的每一笔，按它**自己的尺寸**生成九种画错版本（翻弧 / 压平 / 出头 / 缩放 /
镜像 / 平移 / 折角 / 拖尾 / 歪斜），这样"哪个是原笔""哪根被改坏了"就有了
**构造出来就平衡**的答案，基线不再是前两轮那种"恒定答多数类就能拿 0.4"的偏斜地板，而是真正的 1/K。
错误候选还要过一条**可见度下限** `max(2px, 10%·自身对角线)`——
2px 足够毁掉一条嘴的表情，也会在屋顶上彻底消失，所以固定像素量的"错"是不成立的。
五个家族 64 个 state、522 条判定、243,285 tokens，约 **\$0.010**（\$0.0001–0.0002 一次判断）。

### 8.1 读数（详细逐题见 `results/drawloop/report.md`）

| 实验 | 问什么 | 命中 | 1/K 基线 | 置信度 |
|---|---|---|---|---|
| E1 `pick_shape` | 一句几何意图 + 6 份草稿，哪份是原笔 | **0.80** | 0.166 | 0.236，**10 条全在弃权档** |
| E2 `pair_mate` | 匿名的一笔，对面哪根是它的对称伙伴 | **1.00** | 0.200 | 0.755，ACT 档 3 条全对 |
| E3 `presence` | 抹掉部件后那个词的概率塌不塌 | **AUC 1.00**（6 负例） | 恒定"是" 0.80 | 被抹 0.98→0.04–0.22，幸存者 Δ+0.001 |
| E4 `spot_fault` | 21–24 笔里有一笔是我改坏的 | 开放指控 0.22 / 逐笔 Noul AUC 0.779 | 0.045 | **77.8% 答"都没问题"** |
| E5 `next_stroke` | 看了前 N 笔，下一笔落哪 | **0.083** | 0.204 | 0.577，ACT 档 3 条**全错** |

### 8.2 这一轮的结论

1. **"选"和"找茬"是两回事，差四倍。** 同一批坏草稿：在 6 个候选里挑真的那笔 0.80，
   在 24 笔里指出坏的那笔 0.22，剩下 78% 它谁都不指控。而那 4 次指控里坏笔的 Noul 是 0.53–0.91、
   干净笔最高 0.25–0.30（分离干净）；答不中的 14 题里坏笔 0.15–0.33 与干净笔混在一起甚至更低——
   **它是真没分出来才弃权的，不是敷衍**。所以循环里的接口只能是"代码出题、它答题"，
   不能是"你看看这张有没有问题"。
2. **E1 那 80% 全部落在弃权档。** K=6 的强制选择题分布本来就摊得平（真笔的 p 只有 0.25–0.48），
   答对完全是 argmax 的事。本项目定的 ACT≥0.85 门原样搬过来会把 10 条判断全丢掉，包括 8 条对的。
   **小 K 选择题取 argmax，不看 confidence；要留人就用分布内的"第一名减第二名"。**
3. **它判的是 state 里那几个数字，不是"形状"。** 被稳定拒绝的只有把数字改到人话之外的两类：
   `turn_deg`→0 的压平（平均得票 0.028）和长度砍半的收缩（0.047），随机地板是 0.164；
   保住长度与转折数的镜像 / 缩放 / 折角全停在随机线上（0.145–0.160），
   E1 答错的两条（`hair-1`、`smoke-1`）正是歪斜和缩放。**最反过来说明问题的一条：
   `flip_bulge` 平均偏差 45.4px（这一整轮最猛的几何改动）却只抓到 1/3——把弧翻面是"表情反了"，
   但它一个字段都不毁。**
4. **缺笔检测是免费的，而且它真的在看这张图。** 抹掉 `wall`、`roof`、`tail`、`torso`，
   这些词从 0.98 掉到 0.04–0.22，同一张上其余 8 个词 Δ≤0.01。如果概率来自词表先验而不是这张画，
   删线不会让任何东西动。唯一的软处是命名不唯一对应一笔的词：猫身被抹，`body` 只掉到 0.22，
   因为头和腿的线还在，而"躯干"本来就是从它们的位置推出来的。
5. **下一笔猜不到，而且这不能全怪它。** 0.083 低于随机；"落在笔尖旁边"这条代码规则同一套题上 **0/12**
   （这三幅画的笔顺是主题的：先定地面和身体，再回头补头发）。更关键的是前缀按真笔顺排还是打乱，
   12 个 checkpoint 里 8 个答同一个——**它压根没在读顺序**。它给的是"画家一般会接着画什么"
   （0.96 说该画地面线、0.86 说该画左眼），而题目问的是"这幅画那个人接着画了什么"。
   结合第二轮"读已写下的顺序 1.00"，边界是：**它读得出 state 里的顺序，生成不出 state 外的顺序。**
   真要"下一步"，得由代码把待画部件写成显式清单喂进去。
6. **这一族的高置信度是反向指标**：≥0.85 的三条全错，两条答对的只有 0.23 和 0.33。

最小可用闭环（每笔约 \$0.00018，120 笔的画全程监督约 \$0.02）：
代码写这一笔的几何意图 → 代码生成按可见度下限筛过的 K 份草稿 → E1 取 argmax 选形状
＋ E2 按 confidence 配对称件 → 每若干笔跑一遍 E3 的缺笔清单 → 代码落笔。
E4 那种"这张里有没有画歪"的问法不要出现在循环里，拆成 E1 的形状再用。

这轮的边界要说清：真值是**我的扰动**造的，所以量到的是"能不能把代码改过的线和意图分开"，
比"这条线画得好不好"低一个数量级，**没有任何一条读数关于品味**；
低于可见度下限的错本轮根本没生成；E1 的真那笔是唯一一个"不是别人的仿射变形"的选项，
理论上存在不需要形状知识的取巧解（答错的两条偏向说明它没用，但没做对照排除）；
E1 n=10、E2 n=6，读方向不读小数点；每个 state 都很小（最大 1.4k est tokens），
所以**"一幅 120 笔的画要怎么分块问"这一轮完全没碰**——那既是本轮读数的外推边界，也是下一轮的入口。

### 8.3 怎么跑第三轮

```bash
python -m src.run_drawloop --check  # 离线闸门，不调用 API：答案必须在选项里、K≥3、
                                    # 答案槽位跨 state 均衡（否则"永远选第3个"能白拿）、
                                    # Noul 两边都有类、每个错误候选都过自己的可见度下限
python -m src.run_drawloop          # 5 家族 64 state 网格 -> results/drawloop/raw + summary.json
```

## 9. 第四轮：让它替我画（以及输入端值多少钱）

前三轮都是"我画完它来读"。这一轮反过来：**我出主意，它做判断，脚本落笔**。
我写 19 个记号的配方（窗框 / 窗台 / 月亮 / 竖档 / 背 / 头 / 尾 / 左右耳 / 左右眼 / 鼻 /
左右须 / 左右爪 / 影子 / 左右呼吸），每个配方 2–3 个旋钮、离散取值；代码把网格展开成候选
（我自己的实现 + 从近到远铺开的 5 个邻居，打乱改名 `o-01…`），一个记号一次请求，
选中的数字进 `ctx`——头长在选定的背上，耳朵长在选定的头上，所以这是一幅画而不是 19 道测验题。
36 个旋钮里 **13 个被我的 artist note 钉住**（"背又高又窄"含了 h 和 w），
**23 个留白**（月亮的半径、爪的宽度、影子的长短……）。这个 split 就是题目本身。

同一套题跑两遍，**只改输入端**：`points` 是"6 坨坐标 + 一句人话"；
`facts` 把代码算得出的事实放进 state（旋钮数值、宽高、面积、墨长、与已落笔的距离/穿越/探出量、
镜像伙伴已经选定的数字），再把那句话拆成 15 条可判定子句，每条子句对每个候选各问一次 Noul。

### 9.2 这一轮的结论

1. **上一轮那个"置信度只有 0.35"是我输入端的锅，不是它没品味。** `points` 条件下 6 个候选的
   概率是 0.05/0.12/0.15/0.16/0.16/0.36 —— 我把候选之间的差别藏进点列里让它自己反推。
   把事实写进 state，同一批题的熵从 0.772 掉到 0.554、top1−top2 从 0.267 涨到 0.485。
   **拿到一片平坦的分布，先怀疑 state，再怀疑模型。**
2. **规格能排除，不能指定。** 15 条子句平均把 6 个候选砍到 3.75 个，**一次都没有砍到只剩我那一个**
   （0/12）；而我的实现 12/12 通过自己记号的全部子句。话说得再清楚，剩下的仍是一步品味——
   那一步就是这一轮里唯一需要判断的地方。
3. **它唯一一次钉错，被它自己的验证层抓到了。** 月亮的 `phase` 12→3（把有肉的新月画成牙签），
   而同一份回答里它判定这个候选**不满足**"not a thin sliver"。12 个有子句的记号里
   选择与验证一致的是 11 个。纯代码改一下路由——**只在它自己判定通过子句的候选里取概率最高的**——
   pinned 从 12/13 变 **13/13**，留白那 23 个原样不动（没子句可依）。
   这才是"verify and escalate"在绘画循环里的样子：不是再问一遍"你确定吗"，
   而是让同一个 state 上的两个独立判断互相对账。
4. **对称率 1.0 有一半是我把答案抄进了题面。** 轮到右半边时 `partner_knobs` 就摆在 state 里，
   还附一句"数字一致才对称"——所以 5/5 只能算"关系写进 state 就守得住"，不能算品味。
   证据就是那 0.924 对 0.464 的置信度差。
5. **顺序也是输入端。** 竖档两次都被放在正中央，于是那根档子从猫头上穿过。
   不是它蠢：我的计划把竖档排在猫之前，那次请求里**猫还不存在**，没有任何事实能告诉它
   "正中央将来会坐一只猫"。人画窗户会最后补档子。
6. **它从不喊"六个都不对"**（0/19），和第三轮"78% 说都没问题"一致。
   所以在这个循环里，**"它没拒绝"不能读成"它认可"**。
7. **画完之后：数字几乎不改变"这是什么"。** 四张图是同一套 19 笔、只有数字不同，
   匿名问 10 个句子（笔画改名 e01…，不带记号名），四张图每个词相差 ≤0.08：
   "坐在一个水平面上"0.69–0.77、"有胡须"0.71–0.78、"有两只耳朵"0.70–0.73 都读得出来，
   但**"这张纸里有一只猫"只有 0.30–0.39，连我原创那张也是**，"新月"0.09–0.13。
   随机那张的"尾巴"读到 0.40，比我自己那张（0.26）还高——**这个仪器分辨不了谁画得好**。
   两件事同时成立：这幅画的身份活在我的 plan 里（有哪些笔、什么次序），
   36 个旋钮只决定比例和位置；想让它画出一张*别的*画，要改的是 plan 不是 knob。
8. **中途被自己抓到两次"我在对模型撒谎"**，而 `--check` 都抓不到（闸门管结构，管不了子句
   对我自己的画是否为真）：二次贝塞尔只走到控制点的一半，所以我 note 里"又高又窄的背"
   画出来是 44 宽 × 34 高、比它自己还宽（改了配方让 `h` 就是画出来的高度）；
   `_whisker` 把 `side` 乘进了角度里，于是左右须共用一个 `slope` 却一根上挑一根下掉——
   **数字相同、形状不成镜像，`mirrored_pairs` 那项指标完全看不出来**（改了配方）。

最小可用闭环（一幅画约 \$0.005）：我写配方与网格 → 代码展开候选并把**能算的全部算成事实**
→ 一句 note 拆成可判定子句 → 一次请求里同时拿"选哪个"和"每条子句每个候选过不过"
→ 代码按验证层过滤、再取概率最高 → 落笔，数字进下一个记号的几何。
**不要**把候选的差异留给模型自己从坐标里反推，那一步它给的就只能是平摊的噪声。

这轮的边界要说清：n=19、一个人的一幅画、一套我自己写的配方，所有分母都是十几；
**真值是我，不是世界**——它跟我一致只说明读懂了我的话，不说明画得更好，
而它选了我没想到的更好数字这一轮没有任何仪器能区分（§9.2.7 已明说审计分辨不了）；
候选全部来自我的网格，**它没有发明任何一笔，也不能**；
每次判断读的都是量出来的数，不是渲染出来的图，所以"这一笔视觉上是不是太重"根本没测；
子句是我在看过答案之后写的，虽然闸门禁止子句出现数字，但"我知道钉了哪个值、
于是挑了个恰好描述它的说法"这条偏差没法排除，它对那 13 个 pinned 读数影响最大。

## 10. 总结：四轮之后，什么已经是事实、什么一直欠着

### 10.1 四轮各测了一件事

| 轮 | 它在回答什么问题 | 最强的正面读数 | 最强的负面读数 |
|---|---|---|---|
| 1 画完它读·消融**几何怎么写** | 文本化方式能改变划分质量多少 | 包含、绘制顺序：命中 1.00 / AUC 1.00，且正例占 29%/49% | 读假坐标和读真坐标一样自信；坐标系一置换立刻散架（0.00–0.22，全跌破自己的多数类基线） |
| 2 换有痕迹的画·消融**痕迹怎么写** | 部件归属/层级角色/区域/运动归属这四件真活 | 部件归属 10–11 类全对、ARI 1.000 | 那格主因是元素 id 就是部件名；真笔迹顺序单独只值 **+0.003**，一套自洽的假顺序是负资产 |
| 3 笔还在手里·**循环内判断** | 选候选、配对称件、查缺笔、找画歪的那笔、猜下一笔 | 对称配对 1.00；缺笔检测 AUC 1.00 | **猜下一笔落哪 0.083，低于随机（0.204）**，而且三条进 ACT 档的判断全错；开放问"这里有没有毛病" **77.8% 答"都没问题"** |
| 4 反过来让它替我画 | 我的想法 + 它的判断 + 脚本，能不能成画 | 把事实写进 state：真判断的 14 个记号 0.529 → **0.647**（随机 0.412）；验证层抓到它自己唯一一次钉错 | 整图审计**分辨不了四张图谁画得好**（每个词相差 ≤0.08；"这张纸里有一只猫"0.30–0.39，连我原创那张也是） |

四轮总用量约 **218 万输入 token ≈ \$0.09**（R1 797,423／R2 964,599／R3 243,285／R4 175,243；输出不计费，按 \$0.042/Mtok）。**便宜不是这一串实验的卖点，读数才是要留下的东西。**

### 10.2 可以当事实用的六条（跨轮一致，不是单点读数）

1. **拿到一片平坦的概率分布，先怀疑 state，再怀疑模型。** R1 里同一道题换个文本化就整档位移（归属分组：只给几何 ARI 0.00–0.69 → 带命名 0.94–1.00；九宫格区域：真坐标 0.57–0.86 → 假坐标 0.00–0.22）；R4 里同一批题只换输入端，熵从 0.772 掉到 0.554、top1−top2 从 0.267 涨到 0.485。**我第一版那句"置信度只有 0.35"是输入端的失败，不是能力的上限。**
2. **它划的是"这份 state 叙述的画"，不是真的那张画。** 凡是能从坐标读出来的都准；凡是画师约定（谁代表远景、哪笔属于哪个物体）必须靠命名或作者写的 `<g>` 树。R4 的另一面：**画的身份活在 plan 里，36 个数字只决定比例和位置**——所以"喂得越准它越懂画"这个直觉在表示层就断了。
3. **关系只要写进 state 就守得住；不在 state 里就没有。** 正例：包含/顺序 1.00、镜像伙伴数字写进去之后 5/5 对称（置信度 0.924，是查表不是品味）。反例：R1 无断口线索的前后遮挡 0.53（它读得出谁先画，却不用它推谁在前面）；R4 的竖档——请求发生时猫还不存在，于是没有任何事实能说"正中央将来会坐一只猫"。**顺序和"将来会有什么"也是输入端的一部分。**
4. **开放式"这里有没有毛病"它不指控。** R3 里"这张纸里有一笔是我改坏的"开放问，77.8% 答"都没问题"（同一批材料拆成候选去选就有信息）；R4 里 0/19 从不喊"六个都不对"。所以**"它没拒绝"永远不能读成"它认可"**；要拒绝能力，就得把问题改写成有对照物的判断题。
5. **规格能排除，不能指定。** 15 条可判定子句平均把 6 个候选砍到 3.75 个，**一次都没砍到只剩我那一个（0/12）**。话说清楚之后剩下的一步就是品味——那一步也正是这一轮里唯一值得问的东西。
6. **命中率一律要配基线看，最好是 1/K。** 三次打脸都来自同一处：R3 猜下一笔 0.083 而随机基线是 0.204（**比瞎选还差**）、R1 的相接/交叉 AUC 0.81–0.95 但命中率只比基线高 −0.02 至 +0.07、R4 的对称率 1.0 里有一半是我把答案抄进了题面。

### 10.3 一直欠着的最大一块：**没有一个被改善的量**

四轮里唯一在涨的是"与**我**的一致度"。画得好不好，从头到尾没被测量过——R4 专门试了一次（四张图 × 10 句匿名审计），结果是那把尺分辨不了。三条后果全部悬着：

- **无法区分"它选了我没想到的更好数字"和"它选错了"。** 这一条让 R4 一切读数只能是"读得懂我的规格"，不能是"会画"。
- **所以输入端和路由上的所有收益都只到"更像我这幅画"为止**，pinned 13/13 那个反事实的分母是 13、真值是我，它不是成果，是工程量。
- **样本与自证**：n=19 / 67 笔、一个人的一幅画、配方和子句都是我写的，而且**子句是看过答案之后写的**（闸门只禁止子句出现数字，禁止不了"挑一个恰好描述我钉的值的说法"）。这条偏差对那 13 个 pinned 读数影响最大，我无法排除，只能标出来。

### 10.4 执行端欠得比判断端多

即使判断端明天变成完美的，画出来还是糙——因为问题在执行体：

| 缺什么 | 现状 | 后果 |
|---|---|---|
| 渲染反馈 | 从第一笔到最后一笔，**没有任何环节看过这张画**；所有"事实"是 bbox、质心、墨长、间隙 | 二次贝塞尔只走到控制点一半（我 note 里的"又高又窄"画出来是 44 宽×34 高）、`_whisker` 把 `side` 乘进角度（左右须共用一个 `slope` 却一根上挑一根下掉）。两次都是**我肉眼读数字**抓到的，管线一次都没抓到；而"等宽的一根线是不是太重"这类问题根本没进过循环 |
| 表现力 | 19 笔等宽单折线 | 对比 Astra 那张 `character_refined_v3.svg`：**520 条 path、30 个分组、逐条独立 `stroke-width`（0.35 起一路变化）、闭合三次贝塞尔轮廓**。"糙"字面就在这里，不在判断上 |
| 记号间的挂接 | `_poly(ctx,"shelf")[0][1]`、`_head(ctx)` 这类硬编码取点 | 换一幅画 19 个配方全部重写；顺序不可重排；"这块地方将来要留给猫"无法表示 |
| 候选来源 | 我的配方网格 | **它没有发明过任何一笔，也不能**；网格之外的形状不存在。这是"我的想法+它的判断+脚本"里"想法"那一栏的硬边界 |

### 10.5 两个参考项目：能借的、借不了的

`line-atelier` 的真正资产不是那 29 个 WebMCP 工具，是**一条被程序强制的循环**：观察 → 落 1–3 笔（同对象低风险清线才允许 5–6）→ 回看本批改动目标并登记五项检查 → 才放行下一笔（没完成图像绑定检查，下一次落笔直接拒绝）。另外两件我这边确实缺：坐标带 `kind`（`through` / `bezier-control` / `sampled-trajectory`）并有 `renderedEndpoints`——**源几何和画出来的东西是两个东西**；诊断结果带 `diagnosisId`，**任何画面变化后旧 ID 失效**。
`Astra` 那个仓库只有成品 SVG，没有方法；能借的是目标质量的形状：520 path / 逐条宽度 / 分组 / 闭合轮廓。

| 它们的做法 | 换成 Jev 的对应件 | 换来什么 | 借不到什么 |
|---|---|---|---|
| `paint_inspect_context`：四格对照图 + 带 `kind` 的坐标 | 代码自己光栅化，只报**渲染后**的量：区域墨量、局部间距、负空间、成对部件形状偏差、交叉与遮挡数 | 直接堵掉 §10.4 那两个 bug 的成因；让纯文本模型也能"看到纸" | 它看到的仍是摘要，不是那张图 |
| `diagnosisId` + 画面一变即失效 | 每份判断绑定几何哈希；改了哪一笔 → 只重问受影响的那几题 | 一次性的往下推才变成会回头的循环 | — |
| 程序门（只能查顺序/字段/区域/失效） | 门可以查**内容**：这条候选在"窄而紧凑"上 0.8 不通过 | 它们的判断者和落笔者是同一个模型，门只能查流程；**判断者与作者分离**才是 Jev 在这里的增量：带概率、可复现、一次决策 ~5k token，而它们每次回看是一个视觉模型轮 | 内容的真假仍无人对账（§5.1） |
| 规范正文统一在 `WORKFLOW_PRINCIPLES.md`，五项检查 | 子句来自**外部规范**而不是我自己 | 直接解掉 §10.3 那条"看过答案再写子句"的自证 | 规范是给人读的，翻成可判定子句还是要我动手 |
| 对象 `frame` + 共享 `anchors` | 具名锚点 + 预留区 | 竖档那类顺序问题才有地方表示 | — |

**最大的赌注要说白：Jev 读不了 PNG。** 把画翻译成数字事实，一定会丢东西——丢掉的很可能正是"画"。所以任何一次这样的翻译，都必须配一个"翻译前后排序一致性"的读数，否则整个方向就只是在测它读数字的能力。

### 10.6 现在停在哪

我提过的两条下一步——**用整图两两偏好造刻度**、**先把执行端加厚（宽度/轮廓对/分组）**——都被判为"不太行"。所以本项目当前停在方向待定，我**不再自己加实验**；上面的 §10.3（没有刻度）和 §10.4（执行端欠债）是我能给出的、最接近事实的问题描述，等指示。
