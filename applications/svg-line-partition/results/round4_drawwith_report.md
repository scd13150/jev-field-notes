# 第四轮：让它替我画，以及我上一版是怎么把输入端写坏的

## 0. 一句话

我出主意（19 个记号的配方 + 每个配方的参数网格），它选数字，脚本按数字落笔。
这一轮我把同一套题跑了两遍，**只改输入端**：

- `points`（我第一版）：候选以坐标点列送进去，配一句人话需求。
- `facts`（改过之后）：把代码能算的事实放进 state——每个候选的旋钮数值、量出来的宽高/面积/墨长、它和已经落在纸上的记号差多远、穿不穿过、探出去多少——再把那句人话需求拆成一条条**可判定的子句**，每条子句对每个候选各问一次。

在真正需要判断的那 14 个记号上（另外 5 个我在 state 里直接告诉了它伙伴的数字，见 §3.5）：

| | 随机 | 我上一版的输入 | 改过之后 |
|---|---|---|---|
| 没被规格钉住的旋钮，选中我那个数字 | 7/17 = 0.41 | 9/17 = 0.53 | **11/17 = 0.65** |
| 这些记号上的平均置信度 | — | 0.38 | **0.46** |

上一轮我写下"置信度只有 0.354"，读起来像它对自己的品味没信心。不是。**是我把 6 个候选的差别藏进点列里，让它自己去反推。**同一套题换个输入端，分布立刻有了形状。

## 1. 循环长什么样

```
PLAN = 19 个记号，分四段：窗框/窗台/月亮/竖档 → 背/头/尾 → 耳/眼/鼻/须/爪 → 影子/呼吸
每个记号 = 一个配方函数（我写的） + 2~3 个旋钮（离散取值） + 一句 artist note
每个旋钮 = pinned（我的 note 里含了这个数字，如"背又高又窄"）或 open（note 没管，纯品味）
                36 个旋钮：13 pinned / 23 open
每个记号：代码把配方的网格展开 → 取我自己的实现 + 从近到远铺开的 5 个邻居 → 打乱改名 o-01..o-06
          → 一次请求（一个 forced choice + 验证 fan-out）→ 选中的数字进 ctx → 下一个记号的几何长在它上面
```

一个记号一次请求，不是一次性 fan-out 全部：头的位置长在已经选定的背上，耳朵长在已经选定的头上。**这正是文档说的"需要上一个答案才能构造下一个 state"的情形。**

`python -m src.run_jvdrawing --check` 的离线闸门断言：我的实现一定在候选里；候选 ≥3；任意两个候选的形状平均偏差 ≥0.5px（第三轮的可见度下限用在这里）；没有任何候选越出画布；**子句里不许出现数字**（写了数字就是把答案抄两遍）；**有 pinned 旋钮的记号必须有子句，反之亦然**；候选的 state 里不许再出现 `points`；fan-out 的问题数正好是 1 + 子句数×候选数 + 1。

## 3. 读数

### 3.1 置信度是输入端的函数，不是模型的胆量

`points` 条件下 19 个记号的平均置信度 0.386，归一化熵 0.772——几乎就是把六个候选摇匀。看一个具体返回：`head` 那一题它给六个候选的概率是 0.05/0.12/0.15/0.16/0.16/0.36，confidence 0.24。我当时把这一行读成"Jev 对自己的审美没有把握"。

把旋钮数值和量出来的宽高、面积、探出距离放进 state 之后，同一批题的熵降到 0.554，top1 与 top2 的差从 0.267 涨到 0.485，`tail`/`eye-r`/`paw-r` 直接给到 0.84/0.95/0.99。

**它不是变得有信心了，是终于看得见候选之间差在哪了。** 这条对任何用 Jev 的人都是通用的：如果你拿到一片平坦的概率分布，先怀疑你的 state，再怀疑模型。

### 3.2 唯一有意义的对比，是跟随机放在一起的那 14 个记号

pinned 旋钮上两个条件都是"几乎全中"（11/13、12/13），因为那本来就是我把数字用话说了两遍——它只要听懂话。真正测品味的是 open 旋钮（note 里没管的那些：月亮的半径、窗框的宽、头的半径、尾巴的长短、鼻子的size、爪宽、影子长短、呼吸圈）。

但整体 23 个 open 旋钮里混了 5 个"伙伴已经画过"的记号（耳右/眼右/须右/爪右/呼吸右），我在 state 里明确写了 `partner_knobs` 和"数字一致才对称"。那 5 个已经是查表，不是判断。剔掉：

| 14 个真正需要判断的记号 | 命中我 |
|---|---|
| random | 7/17 = 0.412 |
| jev / points | 9/17 = 0.529 |
| jev / facts | **11/17 = 0.647** |
| middle（永远取网格中档） | 3/17 = 0.176 |

改输入端买到的是 **+12 个百分点**（0.529 → 0.647），而同一子集上随机是 0.412、网格中档是 0.176。
剩下 6 个不一致里，它跟我差得都很近：全部 23 个 open 旋钮的平均相对偏差从 0.371 掉到 0.230——
**即使不同意我，也是往我的方向上不同意。**

### 3.3 子句能把空间砍一半，砍不到一

12 个记号有子句，共 15 条。把每条子句对每个候选各问一次（一次请求里 6~13 个 noul），代码取"所有子句都 ≥0.5"的候选：

- **我自己的实现 12/12 通过自己记号的全部子句**——这条必须先成立，否则整个验证层是噪声（§4 就是它一开始不成立）。
- 平均 6 个候选里活下来 **3.75 个**；**一次都没有缩到只剩我的那个**（0/12）。
- 也就是说：**规格能排除，不能指定。** 我把话说得再清楚，剩下的仍是一步品味。这既是这一轮给"要不要用判断"划的界，也是"我的想法 + 它的判断 + 脚本"三方分工里剩下的那一块。

### 3.4 它唯一一次钉错，被它自己的验证层抓到了

facts 条件下唯一的 pinned 失误是月亮：`phase` 12 → 3，也就是把"有肉的新月"画成了细牙签。
而同一份回答里，六个候选有**五个**被它判定满足"not a thin sliver"，
它偏偏挑了唯一不满足的那个 `o-04`——**而且挑得很有信心：那一题给 `o-04` 的概率 0.57，
比给五个通过子句的候选任何一个（0.05–0.13）都高一个数量级**。
12 个有子句的记号里，它的选择和自己的验证一致的是 11 个（0.917）。

于是可以试一个纯代码的路由：**只在它自己判定通过子句的候选里取概率最高的那个。** 反事实跑下来：

```
pinned 命中  12/13  ->  13/13
open  命中  14/23  ->  14/23   （没子句可依据，原样）
唯一被改写的记号：月亮
```

**一次自相矛盾，恰好就是这一次错误，而矛盾的两边里对的是验证那一层。** 这就是文档里"verify and escalate"在绘画循环里的样子：不是再问它一次"你确定吗"，而是把同一个 state 上的两个独立判断拿来互相对账，让代码发现它们不一致。

### 3.5 对称率 1.0 是我把答案递过去了，得减掉

镜像五对（左右耳、左右眼、左右须、左右爪、左右呼吸）在 facts 条件下 5/5 给出完全相同的一组数字（points 4/5，random 2/5，middle 5/5）。听起来像它"想到了脸要对称"。

实际上是我的 state 写了：轮到右半边时，`partner_knobs` 就摆在里面，还附一句"数字一致才对称"。证据是置信度：

| | 前 14 个（没人告诉它） | 后 5 个（伙伴数字已在纸上） |
|---|---|---|
| jev / points | 0.382 | 0.398 |
| jev / facts | 0.464 | **0.924** |

所以 0.386 → 0.585 这个总涨幅里，有一大块是"我把 5 道题的答案抄进了题面"。**这一条不能算作品味，只能算作：把关系写进 state，它就能守住关系。** 真正属于它的还是那 14 个。

### 3.6 顺序也是输入端：竖档

窗框的竖档（`mullion`）我留了三个位置：偏左 26、正中、偏右 26。我画在偏右，两次它都选**正中**（points、facts 都是），于是那根档子从猫头上穿过去——四张图里都能看到。

不是它蠢。是我的计划把竖档排在猫之前：`mullion` 的那次请求里，纸上只有窗框，**猫还不存在**，没有任何事实可以告诉它"正中央将来会坐一只猫"。人画窗户会最后再补档子。

**记号在计划里的次序，和 state 一样是输入端的一部分。** 下一轮要么把竖档挪到 silhouette 之后，要么在 state 里放一条"预留区"事实（将来这只猫会占 x∈[116,160]）。

### 3.7 它从不喊"六个都不对"

两种条件下，"这六个里没有我要的，需要第七个候选吗"都是 0/19 ≥0.5。和第三轮一致：一旦把问题开成"这里有没有毛病"，它倾向于谁也不指控（那一轮 78% 选 none-match）。**所以在这个循环里，"它没拒绝"不能被读成"它认可"** ——我只能把这道题当成一个独立的存在性判断来记录，不能当成质检结论。

### 3.8 画完之后：数字几乎不改变"这是什么"

四张图（我的、它的、网格中档的、随机的）是**同一套 19 笔**，只有数字不同。把 10 个句子匿名问一遍（笔画改名 e01…，不带任何记号名），四张图在每个词上的差距都 ≤0.08，多数 ≤0.05：

| 问这张纸（四张图的区间） | 概率 |
|---|---|
| 猫坐在一个水平面上 | 0.69–0.77 |
| 有胡须 | 0.71–0.78 |
| 有两只耳朵 | 0.70–0.73 |
| 看起来是睡着而不是醒着 | 0.48–0.53 |
| 室内向外看 | 0.29–0.38 |
| **这张纸里有一只猫** | **0.30–0.39** |
| 有一弯新月 | 0.09–0.13 |
| 有尾巴 | 0.20–0.40 |
| 窗下有影子 | 0.29–0.41 |

两件事，都是负面的，也都是这一轮该报告的：

1. **这个仪器分辨不了谁画得更好。** 随机那张的"尾巴"读到 0.40，比我自己那张（0.26）还高。四张图的排序在每个词上都不构成稳定的差异。所以"Jev 画的比 middle 更像猫"这种话，我没有证据。
2. **但"像不像猫"根本不在这 36 个旋钮手里。** 部件级的词读得出来（0.7 上下），整张图的"是只猫"读不出来（0.3，连我这张原创也是）。也就是说：**这幅画的身份活在我的计划里（有哪些笔、按什么顺序），数字只决定比例和位置。** 想让画换一个是别的画，得改 plan，不是改 knob。
3. 顺带：把审计的 state 从点列换成测量事实之后，部件级词明显上升（"坐在东西上"0.31–0.41 → 0.69–0.77，"影子"0.04 → 0.29–0.41）。但同一批改动也修了身体比例（§4.1），所以这个涨幅不能全记在表示法头上。

## 4. 中途被自己抓到两次"我在对模型撒谎"

这两处都是 `--check` 抓不到的：闸门只能保证结构（子句存在、候选可分、不越界），保证不了**子句对我自己的画是否为真**。是我把 facts 的 state 打出来逐条核对才发现的。

### 4.1 "背是一个又高又窄的拱"——我自己的背是 44 宽 × 34 高

配方用二次贝塞尔 `_quad(p0, ctrl, p2)`，而二次曲线只走到控制点的一半。我把 `h` 当成"画出来的高度"来写 note，实际控制点偏移才是 h，**画出来永远矮一半**。于是 `mine` 的背比它自己宽，而它的子句写着"taller than it is wide"。

如果就这么发出去，验证层会对我的实现判 false（`my_mark_passes` 从 1.0 掉下去），整轮结论都得重写成"作者连自己的画都读错"。改法：控制点取 `y0 - 2h`、`cx + 2*lean`，让 `h` 和 `lean` 就是画出来的量。改完背是 44×68，aspect 0.65，子句为真。

### 4.2 左右胡须共用一个 `slope`，画出来却不对称

`_whisker(side)` 里写的是 `a = radians(-side * slope)`，再 `y = y0 - length*sin(a)`。`side` 被乘进了角度里，于是同一个 slope 下**左须往上挑、右须往下掉**——四张图里那根斜穿过头的直线就是它。这不是判断问题，是我的配方把镜像弄坏了，而 `mirrored_pairs_same_numbers` 这项指标当时完全看不出来（数字相同，形状却不成镜像）。改成 `a = radians(slope)`，`side` 只管 x 方向。

**教训：任何"两个候选只差一点"的生成器，都要用可见度下限去卡；任何声称成对的记号，都要用形状而不是数字去验对称。** 第三轮的闸门已经在卡前者，这一轮我差点把后者漏过去。

## 6. 这一轮不能证明的事

- **n = 19，一个人的一幅画，一套我自己写的配方。** 所有比例的分母都是十几。
- **真值是我，不是世界。** 它跟我一致只说明它读懂了我的话，不说明它画得更好；它跟我不一致也可能是它选了个我没想到的更好数字，这一轮没有任何仪器能区分这两种情况（§3.8 已经明说审计分辨不了）。
- **它没有发明任何一笔。** 候选全部来自我写的配方网格；网格之外的形状它画不出来。这是"我的想法 + 它的判断 + 脚本"里"想法"那一栏的硬边界。
- **它看不见纸。** 每一次判断读的都是代码量出来的数，不是渲染出来的图。所以"这一笔在视觉上是不是太重"这类问题，这一轮根本没测。
- **一次自相矛盾被验证层抓到 ≠ 验证层更可靠。** 12 个记号里只出现一次矛盾，1/12 的样本上比较两层谁准没有意义。
- **子句是我在看过答案之后写的。** 我尽量只把 note 里原有的形容词拆开（"tall and narrow" → 两条），并且闸门禁止子句出现数字，但我无法排除"我知道自己钉了哪个值，所以挑了个恰好能描述它的说法"。这一条对 pinned 那 13 个旋钮的读数影响最大。

## 7. 怎么跑

```bash
python -m src.run_jvdrawing --check                 # 离线闸门，两种输入条件都跑
python -m src.run_jvdrawing --check --input facts
python -m src.run_jvdrawing --input both            # -> results/drawwith/{summary,trace,svg}
python -m src.run_jvdrawing --no-calls              # 只跑代码基线并出图，不计费
```

产物：`results/drawwith/summary_{points,facts}.json`（每个记号的 cell、probs、passes、conf、token），
`{mode}_{mine,jev,middle,random}.svg` 与 `{mode}_compare.html`（四张图并排），
`trace_{mode}_jev_<mark>.json`（每次请求完整的 state / questions / answers，逐条可查）。
`results/cache/` 可以删；删了重跑才会真的再次计费。
