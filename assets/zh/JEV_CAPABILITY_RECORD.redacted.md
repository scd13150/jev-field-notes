## 2. 探索经历（按发现顺序，包含走过的错路）

### 2.1 起点：先读官方文档，定分工

一开始的错法是"让模型复述 .NET 元数据"——这恰是 TypeSafe 文档点名的反模式（程序集本身已经是全类型化的表）。据此定下的原则后来贯穿全程：

> **凡能从字节、表、文件确证的，一律用代码；Jev 只吃"没有真值表"的判断。**

这条原则不是姿态，它后来被两次实测证伪驱动修正（见 §4 T7、§5 B1/B2）。

### 2.2 第一批错报（每一条都被单独纠正并留在报告里）

| 错报 | 真实原因 | 纠正 |
|---|---|---|
| "整个程序集只有 8 个数字" | 只 harvest 了 `ldstr`，没配对 `ldc.*` → `stfld` | 现 **562 个带常量的字段初始化，覆盖 142 个类型** |
| 一个 786/787 的巨型簇 | Noul 概率全为非负，原始向量余弦全接近 1.0 | **必须先按轴中心化+标准化**，否则相似度无意义 |
| 误删 `storage_io` 轴 | 方差门看的是均值（0.08）而非 spread；它在少数真做文件 IO 的类型上峰达 0.89 | 门槛只允许因"无 spread"丢弃轴 |
| 阈值 sweep 报成"平"、与管线差 3 簇 | sweep 脚本**重新实现**了聚类器而不是调用它 | `scripts/val_threshold_shipped.py` 取代旧测量，实测 silhouette 是单调上升 |
| 一条完全失效的轴活过整份报告 | 正例答高 ≠ 轴有效：非判别轴对正例同样答高 | 之后每条轴必须给 **positive-vs-negative gap** |
| 225 个编译器生成状态机混进聚类 | 未过滤 `<...>d` / `CompilerGenerated` | 排除后 `endpoints_generated_leak_count = 0` |

### 2.3 会话被服务端封停（一次运维事故）

旧会话 `926a263d-a24e-4f0c-bc27-4b0f3c43e106` 从 17:05:42 起每个请求都是
`NOT_ACCEPTABLE "Session blocked"`（HTTP 406）、`model_stop_reason: "refusal"`、
`input_tokens: 0`；更早 16:53 有一次上游 `I_AM_A_TEAPOT`（418）拒绝。
判定：**是该会话上下文本身被服务端标记**，重试、改脚本都无效，只能新会话或换模型。
因为所有产物都在磁盘上，工作零损失——这也是下面这些结果能在续接会话里完成的唯一原因。

### 2.4 全场最大的一次根因纠错：ECMA 元素类型表

`scripts/re_model.py` 把 `0x1D` 当作 MVAR。ECMA-335 II.23.1.16 这张表是**稀疏**的——
`0x17` 未分配，因此 I=`0x18`、U=`0x19`、FNPTR=`0x1B`、OBJECT=`0x1C`、**SZARRAY=`0x1D`**、MVAR=`0x1E`。

后果：每个 `T[]` 字段都被读成泛型参数并吞掉后续字节。**168 个程序集、78,621 字段中 1,635 个字段的类型是坏的**，
例如 `ScriptsCollection._scripts` 变成字符串 `m18` 而不是 `ScriptData[]`。
可抓性来自一条硬事实：**MVAR 在字段签名里不可能出现**。判定直接对 blob 字节（`06 1D 12 84 F4`）验证，不靠转述规范。
修复后复测：损坏字段 **1635 → 0**。

### 2.5 三条序列化规则是量出来的，不是假设的

- `UnityEngine.Object` 类型字段就是 12 字节 PPtr（此前 265 个对象只卡在这个类型名上）。
- 委托（`Func`/`Action`/`Predicate`）与普通接口字段不参与序列化。把 `TMP_Text` 的
  `[SerializeField] protected ITextPreprocessor` 当 PPtr 读，会让其后所有字段位移：**MISMATCH 404 → 21**。
- 用到 `[SerializeReference]` 的类型在最后一个声明字段后多 8 字节，实测都是 `[2, 0]`。
  **只按原始字节公布、不命名**，因为它指向什么尚未证明。

### 2.6 修复后重跑语义层，暴露一个归属错误

443 次调用 / 119 命中 / 190 秒 / 记账 $0.035。**miss 数比预估的 251 多**，追查结论：
diff 用的旧 `dossiers.json` 是 16:19 生成的（**已含**嵌套/命名空间修复），而 Jev 缓存最后写入是 15:05
（**尚未含**那次修复）。所以真正失效的是两次修复之和 = 443。
换句话讲：15:05 那次"562 命中 0 调用"的运行，一直把嵌套修复之前的 dossier 当成有效输入。**缓存命中不等于缓存正确。**

## 3. 这个游戏现在被理解到什么程度

### 3.1 四层栈，每层都有可证伪证据

| 层 | 状态 | 凭什么是"做到"而不是"跑过" |
|---|---|---|
| 代码/IL | 完成 | 168 程序集 / 78,621 字段 / 562 真实类型；**4016/4016 方法体全部走通且终止符与声明 code size 精确相等**（过程中抓到 fat-header 偏移与压缩整数端序两处静默 desync） |
| 资产 | 完成 | 11 个 `*_Data` SerializedFile **全部 `_enable_type_tree=False`**（`out/PROBE_BRIDGE.md` §1）→ 用 DLL 合成布局；尺寸预测 **1381/1381 = 100%**；5229 对象 **exact 4658** / MISMATCH 21 / partial 12 / blocked 538 |
| 数值 | 三层打通 | IL 562 常量（程序员兜底默认）←→ 资产 987 数值字段（设计者调好的值，**27 个只存在于资产**）←→ 存档 JSON 运行时状态（25/246 能 join 到真实键，13 个名字唯一，其余标歧义而非默认接受） |
| 语义/架构 | 完成并已复测 | 60 个行为子系统、12 条轴、跨子系统调用边双粒度；行为簇 vs 目录 **NMI 0.502** |

一句话：**被剥掉的 TypeTree 等于从元数据重建出来了。** 一个字段大小错就会让后面全部位移，所以"走 exactly 到对象末尾"是强证明，不是"差不多对"。
第二条独立证据（本轮新增）：把已解码对象里的 **16606 个对象引用**当查询用，`fileID→externals`、
`path_id→m_Name` 还原之后，**158 个剧情文件的引用者全部命中且落在合理的 5 个类上**——
布局若有一位偏移，引用会散落成随机 path_id，不会 158/158 落在真实 TextAsset 上（`out/ink_wiring.json`）。

### 3.2 已识别但按范围未抽取

TextAsset 载荷格式识别：ink **158**、Spine **54**、atlas **44**、other **10**（`out/PROBE_BRIDGE.md` §4）。
Ink 未还原为流程图/线索引，Spine 未还原为骨骼数据。

**但"谁加载哪个剧情文件"这一层已经抽完了，且不碰正文**（本轮新增，`out/ink_wiring.json` +
`out/ink_inventory.json`）：158/158 有主，主只有 **8 个声明槽**（`ActorAppearData.AppearTermsInk`
79、`ActorData.PersistentTermsInk` 36、`ContextSceneScope._scriptDatas` 23、
`ActorAppearData.AppearScript` 15、`StageData.StageStartDialogue` 12、`StageData.StageStartMessages` 11、
`InteractivePhraseController._inkFile` 6、`StageData.StageEndDialogue` 3），27 个文件被两处引用；
声明了却没装 ink 的 `ScriptData.ScriptAsset` 是唯一的空槽。
Ink→C# 的**具名接口**只有 4 个 knot 出现在程序集字符串里、外部函数 1 个（`GetUserName`）、
全局变量 1 个（`userName`）、listDef 0 —— 剧情侧对引擎的控制面比想象中小得多，
真正的数据流在 PPtr 和 knot 词汇表里。四类文件的 knot 词汇表互不重叠，可直接当分类指纹用。

**"60 个行为簇 ≠ 60 个模块"这条现在是量出来的**（本轮 T12 的副产物，0 次调用）：23 个跨命名空间
争议簇的 378 个成员之间只有 **34 条引用边**，其中 **330 个成员在自己簇内一条边都没有**，最大连通
分量 6/16。所以 `map.json` 的簇是**语义相似度分组**，不是可重构的模块边界；要谈"改名/拆分"必须先
用那张簇内引用图（`out/rename_list.json.cohesion_graph_facts`）把候选单元重切成连通分量，
再让 Jev 给分量起名或归类。跨命名空间散布本身**不是**耦合错误的证据。

## 4. Jev 能力测试与证明

每项都给出：设计 / 样本 / 结果 / 结论 / 复现命令。所有数字取自对应 `out/*.json`。

### T1 重复测量稳定性 —— 概率稳、标签不稳
40 类 × 12 次独立抽样（state 里带 uid nonce），400 个 Noul 点。
- SD mean **0.0058**，p50 0.0043，p90 0.0162，p99 0.0281，max 0.0307；range mean 0.0186 / max 0.12
- 跨 0.5 翻转率 **1.75%**；token 逐字一致 **40/40**（max spread 0）→ 是模型自身的非确定性，不是传输噪声
- 但离散标签不稳：role argmax 全一致仅 **95%**，centrality 分档翻转率 **7.5%**
**结论：连续向量可以当回归基线；argmax 标签永远不可以。两次运行之间标签变了，不构成"理解变了"的证据。**
`python scripts/val_v1.py` → `out/val_v1.json`

### T2 校准与风险覆盖 —— 阈值是花出去的覆盖率买来的
182 个判定点（67 正 / 115 负），规则来源：enum 106、hooks+ui_widget 39、scriptable_object 19、anchor_pos 9、anchor_neg 9。
- thr 0.95：accuracy **1.000**，自动通过率 72.5%，MACE 0.0
- thr 0.90：accuracy 0.9879，通过率 90.66%，MACE 0.011
- thr 0.30/0.10：accuracy 0.989，通过率 100%
- 分档：high 132 / medium 50 / low 0
- 分轴校准：`renders_ui` n=94 acc 0.979、`storage_io` n=54（pos 1）acc 1.0、`authoring_config` n=20（pos 19）acc 1.0
**结论：轴不是"对/错"，是"在某个通过率下错多少"。发布任何轴必须同时给通过率。**
`python scripts/val_v2.py` → `out/val_v2.json`

### T3 嵌入空间与阈值 —— 两个常用判据在这里都不可信
17 维 × 562 类型。
- silhouette **0.3281 → 0.4976**，随簇数 24 → 308 **单调上升** → 在此场景有偏，不能选阈值
- resample ARI **0.7779–0.9139**，**无峰** → 稳定性也不能选阈值
- 出厂阈值 0.72 处：56 簇 / 最大 52 / 6 单例 / silhouette 0.3825 / ARI 0.8491；但 ±0.02 内簇数即在摆动
**结论："60 个子系统"是选定分辨率下的一次读数，不是被发现的客观事实。报告必须把阈值当参数公布。**
`python scripts/val_v3.py`；`python scripts/val_threshold_shipped.py`

### T4 调用边复现 —— 宽 ≠ 重
最大跨簇边 **126 个调用点复现一致**，但只覆盖 **6 个 distinct 类型对**；property-accessor 占比 **0.0**（accessor 调用点 0）；生成物泄漏计数 0。
**结论：只按调用点排名会误导（集中扇出被当成广耦合），因此边表同时按"最宽"和"最重"两种粒度报。**
`python scripts/val_v4.py`

### T5 路由策略 —— 把 abstain 变成动作
30 例，floor 0.6，按"分数路由"而非 argmax 决定动作。
- 分数路由结果：`trust_and_keep` 24、`escalate_to_human_review` 6、`flag_for_rename` 0
- 与 argmax 路线分歧 **2 例**；置信度门另触发 **14 次升级，14 次全部能定位到具体是哪一问**
- 对照：改之前 `jev_ask` 只报 argmax 类计数——无动作、无中间带、confidence 白给
**结论：概率只有接上动作才是产物。"不知道"必须落到一个可执行的下一步。**
`python scripts/val_audit_v2.py` → `out/val_v5.json`（文件名与脚本编号不同源，别按 `val_v5.py` 找）

### T6 字段级语义（extField e1/e2/e3）
- **e1** 27 个锚字段 × 4 轴：`extField_e1_full.json` 116 调用 / 130 命中 / 记账 $0.0103；`extField_e1_sample.json` 130 调用 / 0 命中 / $0.0117
- **e2** 无标签词汇归纳（87 调用 / $0.0079）：cluster 0 → `save_load` conf 0.88；`none_of_these` 抓到无法归组的簇（`IAudioService`/`IDialog...` 一类接口簇）

v2 自己报的 `spend_whole_test` $0.01709 含 72 个复用键，不能再与 v1 相加）。

**结论：这一轮没证明新能力，它证明了另外三件事**——(a) 拿"相似度簇"问"是不是一个模块"是错题，
正确的模块证据是那张 34 条边的图，而它已经免费躺在 `out/rename_list.json` 里；(b) 只要证据进了
state，Jev 的分布会朝证据动了（置信度、方向都对），但**动作该不该由它定，取决于一个不存在的真值表**；
(c) 消融是否干净、派生指标是否对齐，都必须由代码断言，不能由作者声明——本轮三个错里两个是
我自己写的代码抓到又没抓到的那种。

## 5. Jev 的能力边界（全部是被测出来的，不是感觉）

- **B1 有名字可读时它会读名字。** T7：两条轴的判别力在遮名后掉掉 60%+，贴错名直接翻负。
- **B2 证据不全时它会答对那个更窄的问题，从而"废掉"一个轴。** T7：+0.79 → +0.12。
- **B3 工件里没有证据的问题就是不可判。** T7：`player_visible` 接地后 +0.01。
- **B4 可枚举的东西不该问它。** 元数据/签名/属性/继承全是免费的精确表；本项目字节层 **0 次调用**，同时 IL 校验抓到 2 处会污染全部语义输入的静默解析错。
- **B5 细粒度分组的重现性有限。** T9：67% / Jaccard 0.51。轴稳，成员不稳。
- **B6 缓存命中 ≠ 缓存正确。** §2.6：一次 0 调用的运行可以整层沿用已经过期的 dossier。
- **B7 它不推数据流，只解名字。** T10：同一批 245 行，遮住名字后从 0.588 掉到 0.302，**低于**"永远答门控"的 0.42，
  argument 类 0/80 全灭。它没有在读指令语义，指令语义要用 `load_bearing_probe.py` 量。
- **B8 tag 不是请求身份。** T10：按 `_tag` 前缀统计成本得 1629 个请求（多算了被否掉的 28 行试点，
  因为 tag 串 `arm:field:rep` 撞上但 state 不同），按 `_key` 统计才是 1470。**统计口径必须以缓存键为准**，
  否则报告里的花费和"这轮到底跑了什么"都会静默失真。
- **B9 置信度防噪声，不防偏置。** T11 零样本臂：158/158 全票选中那个从不被引用的陷阱槽位，
  p_top 0.65~0.84、一致率 1.000、acc 0.000 —— 覆盖率截断在任何一档都救不回来。
  **一个选项集合里存在"听起来最通用的诱饵"时，模型会稳定地全押它，而且很自信。**
- **B10 范例能激活结构匹配，但结构匹配 ≠ 超过查表。** T11：给 8 个范例后 0.907，且遮掉消费者名字
  一分不掉（一致率 0.947）——这是本项目唯一一次消融不掉分；但同样 8 个范例用 knot 集合 Jaccard
  查表得 **0.987，0 次调用**。凡是"给几个配对范例"的判断，**必须先跟最近邻基线比**，否则
  买到的是查表价格推理的票。
- **B11 在"因为脏才被挑出来"的总体上，动作被选择过程预先决定。** T12：23 个争议簇 23/23 判"拆开"，
  而代码算出的簇内引用图也说 0/23 是连通的 —— 此时任何与常数预测器的"一致率"都没有意义，
  100% 同意不等于 100% 能力。**先测退化，再花钱**（T11 是同一个形状的教训）。
- **B12 证据进了 state 会移动分布，不一定移动动作。** T12：把簇内引用图放进 state 后，22/23 单元
  置信度上升（平均 +0.147、最大 +0.61），conf 与边数的秩相关从 −0.46 收紧到 −0.72，
  但**只有 2 个单元真的换档**。所以"读不读证据"要看分布动没动，不能只看路由结果变没变；
  反过来，一个饱和的动作清单（23/23、0 弃权）比一个弃权更多的清单信息量更低。
- **B13 没有真值时能发布的只有排序和公开策略，而且借来的地板可能一条都不放行。** T12 类型臂：
  12 个全部 mean conf < 0.60（4 个恰为 0.00，最高 0.513）→ 自动动作 0 条；但 11/12 三次抽样同档，
  在这里**重复一致性是比地板有效的闸门**。同批 argmax 与最近档路由一致率仅 0.79，
  说明"同一个分布、两种路由"本身就是一个必须公布的分歧率。

## 6. 沉淀下来的分工模型（可直接搬到别的项目）

1. **代码确证字节/表/文件，Jev 只吃没有真值表的判断。** T10 给了这条一个数：同一件事，
   确定性探针 8 秒 0 调用拿到 245 个标签，Jev 花 $0.051 只做到 0.588（其中 +0.286 是名字带来的）。
2. 每条新轴过三关：**正例 → positive/negative gap → 遮名消融**，三关全过才发布。
3. **概率当回归基线，argmax 标签不当。** 对比运行差异要看概率分布。
4. 阈值一律作为**参数**公布，并给 ±0.02 敏感性；不要宣称"发现了 N 个模块"。
5. **弃权是产物**：conf 0.00 + 定位到具体问题 = 下一张调查清单。
6. 语义层输入（dossier）变更后**强制复测缓存归属**，别把"全命中"当"全对"。
7. 记账只认每次运行自己的 `J.stats()` 差值，共享日志只能看趋势；要报"这个测试一共花了多少"，
   就按**缓存键**汇总（`cache_spend`），别按 tag——B8。
8. 报告里的数字尽量从侧车读（`authored_values.json`、`map_pre_szarray.json`），手写数字必然腐烂——本项目实际腐烂过两次。
9. **任何"给范例"的判断先跑一个确定性最近邻基线**（T11：查表 0.987 > Jev 0.907，0 成本）。
   基线不是装饰，它是决定这条流水线要不要存在的东西。
10. **选项集合里放诱饵要谨慎**：`ScriptData.ScriptAsset` 这种"声明了但没用过"的选项让零样本臂
    158/158 全错且自信（B9）。要么把诱饵也放进范例，要么在评分里单独看命中诱饵的行。
11. **消融要连真值一起消融**：遮名臂的标签必须翻译成同一套匿名 id 再评分，否则正确的判断会被
    判成 0 分（T11 的第一版就是这么错的）。
12. **消融必须由代码证明"剥干净了"**，不能靠"我把那个字段删了"。T12：`no_folder` 第一版只删
    `namespace` 字段，而签名里的完整限定名把整棵树原样送了出去；现在的做法是花钱之前拿全部
    106 个命名空间在消融后的 JSON 里搜 `ns + "."`，命中即 abort。
13. **每个派生指标都要先在自己的定义上自检。** T12：两臂的阶梯档数不同（3 档 / 2 档）却共用一个
    `split_of()`，把 2/23 的翻转报成 22/23；原始数据全对，只有指标反了。凡是跨臂比较的度量，
    写的时候就用手推一个已知应该/不应该翻转的例子。
14. **问"是不是一个模块"之前，先算引用图。** 相似度簇、命名空间散布、嵌入距离都不是模块证据；
    T12 里 378 个成员只有 34 条簇内边，于是"23/23 该拆"既是错的题、也是常数答案（B11）。
15. **写进生成型报告的 caveat 必须待在生成器里，不能手改进输出。** 本轮把 T10/T12 的结论补进
    `out/ARCHITECTURE.md` 时顺手重跑了 `scripts/extField_report.py`，结果它把一段只存在于
    `out/SEMANTICS.md` **输出文件**里的"Provenance caveat"整节删掉了（那个文件 408 行里只有这一段
    不是生成的）。已把该段原样搬进生成器并用 `diff` 证明重跑后除新增说明外零差异。推论：
    **凡改生成型文档，先 diff 再重跑**；能在生成器里按文件 mtime 算出来的版本事实，就不要手抄数字。
