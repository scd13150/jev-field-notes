# Jev 实测记录

**用 TypeSafe Jev（System One）做的三个应用、一份边界分析,以及一套可复现的测量方法。**

[English](README.md) · 中文

[![checks](https://github.com/scd13150/jev-field-notes/actions/workflows/checks.yml/badge.svg)](https://github.com/scd13150/jev-field-notes/actions/workflows/checks.yml)
[![license: MIT](https://img.shields.io/badge/code-MIT-blue.svg)](LICENSE)

Jev 常被介绍成"一个很快很小的模型"。用下来我的结论是:**它真正的价值是边界清楚——它把"关于语义的问题"变成有类型、有概率、能被代码放进循环里的调用,前提是你别拿它去做它有真值表就能做的事。**

这份记录里最重要的不是"它能做什么",而是**"它不该被问什么"**,而且每一条都有实测数字。

## 三个应用,三个互不相关的领域

### 1. 实时格斗游戏 — [`applications/stick-figure-fighter`](applications/stick-figure-fighter)

一次 Jev 往返 **0.4–1.3 秒**,而一帧只有 **16.7 毫秒**。所以模型**不可能逐帧去问**。

做法:每次请求给六个并行判断(**2 个 Choice + 3 个 Noul + 1 个 Score**,共享同一份状态),构成一个**持续意图**;由代码里的反射以 60Hz 执行。引擎自己的几何函数同时给判断层和碰撞层用——**判定几何只有一个真值来源**。

- **52 个测试**,不需要密钥、不需要网络
- 一个同形状的**离线孪生**(mock),让整套台账完全确定性:同一个 mock 池在 Windows 本地和 Ubuntu CI 上跑出**完全相同的数字**(防御占比 21.3%、连段上限 5 段)
- 台账只从引擎的事件流派生指标,**绝不从帧数据反推**——这样"改一条策略"能被证伪而不是被解释掉

**这条经验可以直接搬:慢模型 + 快代码 = 能用的实时系统。模型给持续意图,代码按帧执行。**

### 2. 情感语音 — [`applications/emotion-controlled-tts`](applications/emotion-controlled-tts)

Jev 读一句台词加一份角色档案,给出分级的判断;代码把它映射成 **8 维情绪向量**(喜/怒/哀/惧/厌恶/抑郁/惊讶/平静)加时长因子,驱动 **IndexTTS 2.5**。

三组 A/B,每组的 A/B 只有"有没有注入情绪向量"这一个差别。频谱图**按对归一化**——所以看得见的差异是音色,不是音量(实测 B 比 A 响 +1.7 / +2.8 / +1.8 dB,这个差被印在图上而不是藏起来)。

### 3. 能力上限探针 — [`applications/svg-line-partition`](applications/svg-line-partition)

这个应用**故意设计成会失败**:把元素之间的坐标随机置换(假证据对照),看它还能不能判断。

> 区域判断准确率 **0.857 → 0.048**,跌破它自己的多数类基线;而**置信度只动了 0.026**。

**结论:置信度衡量的是"这份 state 里有没有可依据的线索",不是"线索是不是真的"。** 上游数据必须由代码自己保证正确,这一步不能外包给模型。

## 边界分析 — 最该看的一份

[`papers/JEV_EMPIRICAL_BOUNDARY_ANALYSIS.md`](papers/JEV_EMPIRICAL_BOUNDARY_ANALYSIS.md) · 中文原件:[`assets/zh/JEV_CAPABILITY_RECORD.redacted.md`](assets/zh/JEV_CAPABILITY_RECORD.redacted.md)

**8,000+ 次调用 / 17,156,453 输入 token / 合计 $0.72**(p50 383ms,p90 806ms,错误 0)。

关键在**评分基准不是我的意见,而是硬真值**:指令流(3,959 个方法体、82,765 条 IL 指令)、字节级布局(尺寸预测 1381/1381 命中)、16,606 个对象引用。

**测出来的三条:**

**① 遮名消融 —— 它的优势来自读名字,不是读语义。**
同一个角色分类任务:保留真名 **0.588**,遮成 `Class_NN.field_NN` 后掉到 **0.302**——**低于"永远答多数类"的 0.42**。也就是说 **+0.286 来自解码命名约定**。要推断指令语义,直接跑那个探针:**0 次调用、8 秒**。

**② 置信度防噪声,不防偏置。**
一个 9 选项路由任务里,零样本把 **158/158 次调用**全押在一个听起来合理、但**从未被引用**的诱饵槽位上,置信度 0.65–0.84,准确率 **0.000**;而一个免费的 1-NN 基线拿到 **0.987**。
→ **选项集合里放"听起来最通用"的诱饵要小心,模型会稳定地全押它,而且很自信。**

**③ 剪枝反而变差(这一条和官方 SDK 建议对上了)。**
20 个候选时它选对(conf 0.54);用谓词缩到 3 个之后,它把概率推给了退出项——首问命中率 **62.5% → 37.5%**。这独立验证了官方文档"给全量列表而不是 shortlist"的建议。

## 中文场景实测(这一条只在中文侧有)

同一批素材、同一组英文问题,**只把 state 的语言从英文换成中文**:

| | 结果 |
|---|---|
| 英文 | **3/3 判对** |
| 中文 | **1/3 判对** |
| 两个错答的置信度 | **0.31 / 0.53** |
| 三个答对的置信度 | **全部 ≥ 0.82** |

**所以一个约 0.6 的阈值加上按置信度分流,就能自动把这两个错误拦下来。**

**这是可落地的工程做法,不是模型缺陷:**
1. 判别用的字段**保留一份英文镜像**(原文仍是画面/文案的权威)
2. 按置信度分档:高 → 自动执行;中 → 执行但标记复核;低 → **不执行**,转人工

注意:**用中文写"问题"没测过**,别假设可行。

## 常用原则(可直接搬到别的项目)

1. **能从字节/表/文件确证的,一律用代码。** Jev 只吃"没有真值表"的判断。
2. **每条新轴过三关:** 正例 → positive/negative gap → **遮名消融**。三关全过才发布。
3. **概率当回归基线,argmax 标签不当。** 对比运行差异要看概率分布。
4. **任何"给几个范例"的判断,先跑一个确定性最近邻基线。** 本项目里查表 0.987 > Jev 0.907,而且是 0 成本。
5. **阈值一律作为参数公布**,并给敏感性区间;不要宣称"发现了 N 个模块"。
6. **弃权是产物。** 置信度 0.00 加上能定位到具体哪一问 = 下一张调查清单。
7. **模型版本要钉死。** `jev-latest` 是会漂移的别名;升级模型按编译器升级对待(全量重跑 + diff)。

完整 16 条见 [`docs/FINDINGS.md`](docs/FINDINGS.md)。
